Type inference

1. The problem

Example (untyped). One identity function:

\[ \lambda x.\, x \]

Example (STLC). One identity function per type:

\[ \begin{aligned} \lambda x{:}\mathsf{bool}.\, x &: \mathsf{bool} \to \mathsf{bool} \\ \lambda x{:}\mathsf{bool} \to \mathsf{bool}.\, x &: (\mathsf{bool} \to \mathsf{bool}) \to (\mathsf{bool} \to \mathsf{bool}) \\ &\ \ \vdots \end{aligned} \]

Goal. Write \(\lambda x.\, x\) and let the checker find the type: \(\alpha \to \alpha\), with each type above an instance of it (section 4).

Definition. Drop the annotation, and add type variables:

\[ \begin{aligned} \tau &::= \mathsf{bool} \mid \tau_1 \to \tau_2 \mid \alpha \\ e &::= x \mid \lambda x.\, e \mid e_1\, e_2 \mid \mathsf{true} \mid \mathsf{false} \mid \mathsf{if}\ e\ \mathsf{then}\ e_1\ \mathsf{else}\ e_2 \end{aligned} \]

\(\alpha, \beta\) are type variables.

3. Solve them

Where we are. From the two runs:

\[ \begin{aligned} &\vdash \lambda x.\, \mathsf{if}\ x\ \mathsf{then}\ \mathsf{false}\ \mathsf{else}\ \mathsf{true} : \alpha \to \mathsf{bool} \mid \{\alpha = \mathsf{bool},\ \mathsf{bool} = \mathsf{bool}\} \\ &\vdash \lambda x.\, x\ \mathsf{true} : \alpha \to \beta \mid \{\alpha = \mathsf{bool} \to \beta\} \end{aligned} \]

A type, and constraints on its type variables. Now what?

First example. \(\mathsf{bool} = \mathsf{bool}\) is obvious information. Discard it:

\[ \vdash \lambda x.\, \mathsf{if}\ x\ \mathsf{then}\ \mathsf{false}\ \mathsf{else}\ \mathsf{true} : \alpha \to \mathsf{bool} \mid \{\alpha = \mathsf{bool}\} \]

The expression has type \(\alpha \to \mathsf{bool}\) where \(\alpha = \mathsf{bool}\). So it should just be \(\mathsf{bool} \to \mathsf{bool}\).

Second example. The expression has type \(\alpha \to \beta\) where \(\alpha = \mathsf{bool} \to \beta\). So it should just be \((\mathsf{bool} \to \beta) \to \beta\).

This process is called unification: take the candidate type our algorithm inferred, and use the constraints to refine it. If the constraints are contradictory, the program does not type check.

What does a solution look like?

"\(\alpha = \mathsf{bool}\), so replace \(\alpha\) by \(\mathsf{bool}\)": a substitution.

Definition. A type substitution (or instantiation) is a finitely supported function

The best one is \(\alpha \to \alpha\): if \(\vdash \lambda x.\, x : \tau'\), then \(\tau' = (\alpha \to \alpha)[S]\) for some \(S\).

Definition. \(\tau \sqsubseteq \tau'\) if \(\tau' = \tau[S]\) for some \(S\): \(\tau'\) is an instance of \(\tau\).

Bold: the types of \(\lambda x.\, x\). The lowest one, \(\beta \to \beta\), is its principal type.

Remark. Why \(\beta \to \beta\)? It is a type of \(\lambda x.\, x\), and every type of \(\lambda x.\, x\) has the form \(\tau \to \tau = (\beta \to \beta)[\beta \mapsto \tau]\): all of them sit above it.

Why not \(\alpha\)? It is lower, but it is not a type of \(\lambda x.\, x\). A \(\lambda\) always has a function type, and \(\alpha\) is not one. The principal type must itself be a type of the term.

Definition. The principal type of \(e\), if it exists, is a type \(\tau\) such that if \(\vdash e : \tau'\), then \(\tau' = \tau[S]\) for some \(S\). In that case \(\tau'\) is an instantiation of \(\tau\).

Non-example. \(\mathsf{bool} \to \mathsf{bool}\) is not principal for \(\lambda x.\, x\). The type \((\mathsf{bool} \to \mathsf{bool}) \to (\mathsf{bool} \to \mathsf{bool})\) is not an instantiation of it.

Remark. A principal type is unique up to renaming. \(\alpha \to \alpha\) and \(\beta \to \beta\) are instantiations of each other.
