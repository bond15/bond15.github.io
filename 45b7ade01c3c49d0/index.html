1. Do all STLC programs terminate?

Lecture 14 ended with a question. The fixed-point combinators \(\Omega\) and \(Y\) cannot be typed, so maybe no looping program can be written at all:

\[ \textbf{Theorem (termination).}\quad \text{If } \vdash e : \tau \text{ then } e \longrightarrow^* v \text{ for some value } v. \]

Untyped λ-calculus and IMP both fail this: \(\Omega\) and \(\mathsf{while}\ \mathsf{true}\ \mathsf{do}\ \mathsf{skip}\) run forever.

Why this means STLC is not Turing complete

Rice's theorem: in a Turing-complete language, no non-trivial semantic property of programs is decidable. But if every closed \(e : \mathsf{int}\) terminates, the property "\(e\) is equivalent to \(0\)" is decidable: run \(e\) (it stops, since the step relation is computable and the run is finite) and look at the number. It is non-trivial: \(1\) does not have it. So STLC cannot be Turing complete. In untyped λ-calculus the same test only gives a semi-decision procedure, because the run might not stop.

Whether this is good or bad depends on what you want. Smart contracts, configuration languages, and the core languages of Lean and Rocq all want termination; for Rocq it is what makes the proof assistant sound as a logic.

terminates e is the conclusion of the theorem: a value that \(e\) reaches.

Attempt 1: induction on the typing derivation

The obvious plan. The variable case is vacuous, since no variable is closed, and a λ is already a value. The application case is where it goes wrong.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad \vdash e_1 : \tau_1 \to \tau_2 \qquad \vdash e_2 : \tau_1 \\[6pt] \class{hl-blue}{\bbox[#eef1f6,2pt]{e_1 \longrightarrow^* v_1 \qquad e_2 \longrightarrow^* v_2}} \end{gathered} \]

Inversion gives the two premises. The inductive hypotheses give a value for each.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad \vdash e_1 : \tau_1 \to \tau_2 \qquad \vdash e_2 : \tau_1 \\[6pt] e_1 \longrightarrow^* v_1 \qquad e_2 \longrightarrow^* v_2 \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{v_1 = \lambda x{:}\tau_1.\, e_1'}} \end{gathered} \]

By preservation \(v_1\) has the function type, so by canonical forms it is a λ.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad \vdash e_1 : \tau_1 \to \tau_2 \qquad \vdash e_2 : \tau_1 \\[6pt] e_1 \longrightarrow^* v_1 \qquad e_2 \longrightarrow^* v_2 \qquad v_1 = \lambda x{:}\tau_1.\, e_1' \\[6pt] e_1\, e_2 \longrightarrow^* (\lambda x{:}\tau_1.\, e_1')\, e_2 \longrightarrow^* (\lambda x{:}\tau_1.\, e_1')\, v_2 \longrightarrow \class{hl-blue}{\bbox[#eef1f6,2pt]{e_1'[x \mapsto v_2]}} \end{gathered} \]

Run the function, run the argument, take the β step.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad \vdash e_1 : \tau_1 \to \tau_2 \qquad \vdash e_2 : \tau_1 \\[6pt] e_1 \longrightarrow^* v_1 \qquad e_2 \longrightarrow^* v_2 \qquad v_1 = \lambda x{:}\tau_1.\, e_1' \\[6pt] e_1\, e_2 \longrightarrow^* (\lambda x{:}\tau_1.\, e_1')\, e_2 \longrightarrow^* (\lambda x{:}\tau_1.\, e_1')\, v_2 \longrightarrow e_1'[x \mapsto v_2] \\[6pt] \class{hl-blue}{\bbox[#eef1f6,2pt]{\text{Need: } e_1'[x \mapsto v_2] \text{ terminates. Nothing says so.}}} \end{gathered} \]

The hypotheses are about \(e_1\) and \(e_2\). About \(e_1'[x \mapsto v_2]\), a term that came out of running them, we know only that it is well typed. Stuck.

"But it is well typed, so the inductive hypothesis applies" is the tempting mistake. The inductive hypothesis is for subderivations, and the derivation of \(e_1'[x \mapsto v_2]\) is not one: \(v_2\) is copied into every \(x\), so it can be bigger than the derivations of \(e_1\) and \(e_2\) together. No size measure rescues it.

In Rocq, preservation along a run is assumed (it is Discussion 6's preservation, iterated) and the proof is stepped to the point where it stops. Run the block and read the goal: a value that \(e_1'[x \mapsto v_2]\) reaches, with nothing about \(e_1'[x \mapsto v_2]\) in the hypotheses.

Strengthen the inductive hypothesis

The statement \(P\), "\(e\) reaches a value", is not an inductive invariant: it is not closed under the rules. The way out sounds backwards. Instead of \(P\), prove a harder statement \(Q\) with \(Q \Rightarrow P\). Harder to establish on the way out, but on the way in the inductive hypothesis now says \(Q\), and that is more to work with. Type safety was the same move: "doesn't go wrong" is \(P\), "well typed" is \(Q\).

Where to find \(Q\): look at where the proof got stuck. We had \(v_1\) of function type and wanted \(v_1\, v_2\) to terminate. So ask for that in the statement: the value a function-typed term reaches must send good arguments to terminating applications.

The logical relation

Two predicates, defined together by recursion on the type. \(\mathcal{V}_\tau\) is the set of good values at \(\tau\); \(\mathcal{E}_\tau\) is the set of good expressions, the ones that reduce to a good value.

\[ \mathcal{V}_{\mathsf{int}} = \{\, n \mid n \in \mathbb{Z} \,\} \qquad\qquad \mathcal{V}_{\mathsf{bool}} = \{\, \mathsf{true}, \mathsf{false} \,\} \]
\[ \mathcal{V}_{\tau_1 \to \tau_2} = \{\, v \mid \forall v' \in \mathcal{V}_{\tau_1}.\ v\, v' \in \mathcal{E}_{\tau_2} \,\} \]
\[ \mathcal{E}_\tau = \{\, e \mid e \longrightarrow^* v \text{ and } v \in \mathcal{V}_\tau \,\} \]

A good function value is one that behaves well under the elimination form: applied to a good value, it gives a good expression. Almost every logical relation treats functions this way. Base types list their canonical values. This is a logical predicate; "relation" is the name of the technique.

In Rocq, \(\mathcal{V}_{\tau_1 \to \tau_2}\) also records that \(v\) is a value and that \(\vdash v : \tau_1 \to \tau_2\). The lecture takes both for granted, since \(\mathcal{V}_\tau\) is a set of closed values; the proof needs them written down.

The two relations as one recursive definition on the type, with \(\mathcal{E}\) written out inside the function clause, and then as its own definition.

Two facts read straight off the definition: a good value is a value, and a good value is well typed.

Anti-reduction. If \(e' \in \mathcal{E}_\tau\) and \(e \longrightarrow e'\), then \(e \in \mathcal{E}_\tau\): it reaches the same good value, one step later. Obvious, and used in every case below.

Attempt 2: the stronger statement, for closed terms

\[ \text{If } \vdash e : \tau \text{ then } e \in \mathcal{E}_\tau. \]

Shorter than before, and it implies termination, since \(\mathcal{E}_\tau\) says \(e\) reaches a value. The application case now goes through:

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad e_1 \in \mathcal{E}_{\tau_1 \to \tau_2} \qquad e_2 \in \mathcal{E}_{\tau_1} \\[6pt] e_1 \longrightarrow^* v_1 \in \class{hl-blue}{\bbox[#eef1f6,2pt]{\mathcal{V}_{\tau_1 \to \tau_2}}} \qquad e_2 \longrightarrow^* v_2 \in \mathcal{V}_{\tau_1} \end{gathered} \]

The inductive hypotheses now say more: \(v_1\) is a good function value. The contravariant side of the strengthening.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad e_1 \in \mathcal{E}_{\tau_1 \to \tau_2} \qquad e_2 \in \mathcal{E}_{\tau_1} \\[6pt] e_1 \longrightarrow^* v_1 \in \mathcal{V}_{\tau_1 \to \tau_2} \qquad e_2 \longrightarrow^* v_2 \in \mathcal{V}_{\tau_1} \\[6pt] \class{hl-blue}{\bbox[#eef1f6,2pt]{v_1\, v_2 \in \mathcal{E}_{\tau_2}}} \end{gathered} \]

By the definition of \(\mathcal{V}_{\tau_1 \to \tau_2}\), applied to \(v_2\). This is what was missing before.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad e_1 \in \mathcal{E}_{\tau_1 \to \tau_2} \qquad e_2 \in \mathcal{E}_{\tau_1} \\[6pt] e_1 \longrightarrow^* v_1 \in \mathcal{V}_{\tau_1 \to \tau_2} \qquad e_2 \longrightarrow^* v_2 \in \mathcal{V}_{\tau_1} \\[6pt] v_1\, v_2 \in \mathcal{E}_{\tau_2} \qquad e_1\, e_2 \longrightarrow^* v_1\, v_2 \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{e_1\, e_2 \in \mathcal{E}_{\tau_2}}} \end{gathered} \]

Anti-reduction: \(e_1\, e_2\) runs to \(v_1\, v_2\), which is good.

And the λ case, which used to be trivial, now fails. This is the covariant cost of strengthening: more to prove.

\[ \begin{gathered} \textbf{Case } e = \lambda x{:}\tau_1.\, e'. \qquad x{:}\tau_1 \vdash e' : \tau_2 \\[6pt] \lambda x{:}\tau_1.\, e' \longrightarrow^* \lambda x{:}\tau_1.\, e' \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{\text{Need: } \lambda x{:}\tau_1.\, e' \in \mathcal{V}_{\tau_1 \to \tau_2}}} \end{gathered} \]

A value, so it reaches itself. Before, that was the whole case. Now the value must be good.

\[ \begin{gathered} \textbf{Case } e = \lambda x{:}\tau_1.\, e'. \qquad x{:}\tau_1 \vdash e' : \tau_2 \\[6pt] \text{Let } v_1 \in \mathcal{V}_{\tau_1}. \qquad (\lambda x{:}\tau_1.\, e')\, v_1 \longrightarrow e'[x \mapsto v_1] \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{\text{Need: } e'[x \mapsto v_1] \in \mathcal{E}_{\tau_2}}} \end{gathered} \]

Take a good argument, β-reduce, and by anti-reduction it is enough to show the body with \(v_1\) substituted is good.

\[ \begin{gathered} \textbf{Case } e = \lambda x{:}\tau_1.\, e'. \qquad x{:}\tau_1 \vdash e' : \tau_2 \\[6pt] \text{Let } v_1 \in \mathcal{V}_{\tau_1}. \qquad (\lambda x{:}\tau_1.\, e')\, v_1 \longrightarrow e'[x \mapsto v_1] \qquad \text{Need: } e'[x \mapsto v_1] \in \mathcal{E}_{\tau_2} \\[6pt] \class{hl-blue}{\bbox[#eef1f6,2pt]{\text{No inductive hypothesis for } e': \text{ it is not closed.}}} \end{gathered} \]

Look familiar? The theorem is about closed terms, and \(e'\) has \(x\) free. The inductive hypothesis for it is vacuous.

Two failures, two lessons. The first time the hypothesis said too little about the value. The second time it said nothing about open terms, although induction on typing derivations passes through them at every λ.

Attempt 2 in Rocq. The application case closes; the proof stops at the λ case, where the inductive hypothesis has nothing to say. Run the block and read the goal.

Closing substitutions

The second fix sits on top of the first; nothing already built is thrown away. A term typed under \(\Gamma\) becomes closed when every variable of \(\Gamma\) is replaced by a value. So define the good substitutions for \(\Gamma\), by recursion on \(\Gamma\):

\[ \mathcal{G}_{\cdot} = \{\, \cdot \,\} \qquad\qquad \mathcal{G}_{\Gamma, x:\tau} = \{\, (\gamma, x \mapsto v) \mid \gamma \in \mathcal{G}_\Gamma,\ v \in \mathcal{V}_\tau \,\} \]
\[ \Gamma \models e \in \tau \quad:=\quad \forall \gamma \in \mathcal{G}_\Gamma.\ e[\gamma] \in \mathcal{E}_\tau \]

\(e[\gamma]\) is the simultaneous substitution: \(e\) with every variable in \(\gamma\) replaced. The single turnstile \(\vdash\) is syntax; the double turnstile \(\models\) is the semantic judgement. You know the notation is right when it gets short.

On paper, substitutions commute and closed terms are left alone by them, and nobody writes the proofs. In Rocq they are seven short lemmas, by induction on the term or on \(\gamma\). Folded; the names say what they do.

Free variables, and closed terms: terms with none.

A free variable of a well-typed term is in its context, so a closed well-typed term has no free variables.

Substituting for a variable that is not free changes nothing; substituting a closed value kills the variable; two substitutions for different variables commute.

A closed term is unchanged by a closing substitution, and a single substitution can be done before or after a closing substitution that does not mention its variable.

How \(e[\gamma]\) goes through each form of \(e\): a variable becomes its value, an application substitutes into both sides, a λ substitutes into its body with the bound variable dropped from \(\gamma\).

Facts about good substitutions: their values are closed, every variable of \(\Gamma\) is sent to a good value of its type, and dropping \(x\) keeps a good substitution good.

Lookup after dropping and after appending; the typing of \(e[\gamma]\), by the substitution lemma once per variable; and the context swap used at a λ, where \(\Gamma, x{:}\tau_1\) is read as \(\Gamma\) with its old \(x\) dropped.

The fundamental theorem

\[ \textbf{Theorem (fundamental).}\quad \text{If } \Gamma \vdash e : \tau \text{ then } \Gamma \models e \in \tau. \]

Sometimes the fundamental lemma, for modesty. By induction on the typing derivation, and now every subterm has a useful hypothesis, because every subterm is typed under some \(\Gamma\). Three cases to watch:

\[ \begin{gathered} \textbf{Case } e = x. \qquad x{:}\tau \in \Gamma \qquad \text{Let } \gamma \in \mathcal{G}_\Gamma. \\[6pt] \class{hl-blue}{\bbox[#eef1f6,2pt]{x[\gamma] = v \in \mathcal{V}_\tau}} \end{gathered} \]

No longer trivial, but easy: \(\gamma\) sends \(x\) to a good value by the definition of \(\mathcal{G}\), and a good value is a good expression.

\[ \begin{gathered} \textbf{Case } e = e_1\, e_2. \qquad \text{Let } \gamma \in \mathcal{G}_\Gamma. \qquad (e_1\, e_2)[\gamma] = e_1[\gamma]\ e_2[\gamma] \\[6pt] e_1[\gamma] \in \mathcal{E}_{\tau_1 \to \tau_2} \qquad e_2[\gamma] \in \mathcal{E}_{\tau_1} \qquad \text{then as in attempt 2} \end{gathered} \]

Substitution goes into both sides; the inductive hypotheses apply; the rest is the application case already done.

\[ \begin{gathered} \textbf{Case } e = \lambda x{:}\tau_1.\, e'. \qquad \Gamma, x{:}\tau_1 \vdash e' : \tau_2 \qquad \text{Let } \gamma \in \mathcal{G}_\Gamma. \\[6pt] (\lambda x{:}\tau_1.\, e')[\gamma] = \lambda x{:}\tau_1.\, e'[\gamma] \qquad \text{Let } v_1 \in \mathcal{V}_{\tau_1}. \qquad (\lambda x{:}\tau_1.\, e'[\gamma])\, v_1 \longrightarrow e'[\gamma][x \mapsto v_1] \end{gathered} \]

Substitution goes under the λ (by α-equivalence, no clash). Take a good argument and β-reduce, as before.

\[ \begin{gathered} \textbf{Case } e = \lambda x{:}\tau_1.\, e'. \qquad \Gamma, x{:}\tau_1 \vdash e' : \tau_2 \qquad \text{Let } \gamma \in \mathcal{G}_\Gamma. \\[6pt] (\lambda x{:}\tau_1.\, e')[\gamma] = \lambda x{:}\tau_1.\, e'[\gamma] \qquad \text{Let } v_1 \in \mathcal{V}_{\tau_1}. \qquad (\lambda x{:}\tau_1.\, e'[\gamma])\, v_1 \longrightarrow e'[\gamma][x \mapsto v_1] \\[6pt] e'[\gamma][x \mapsto v_1] = e'[\gamma'] \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{\gamma' = (\gamma, x \mapsto v_1) \in \mathcal{G}_{\Gamma, x:\tau_1}}} \qquad \text{so } e'[\gamma'] \in \mathcal{E}_{\tau_2} \end{gathered} \]

The two substitutions combine into one good substitution for the extended context. That is exactly the inductive hypothesis for \(e'\). Done.

In Rocq the induction is on the term \(e\), inverting the typing rule at each step, rather than on the derivation: at a λ the context has to change, from \(\Gamma, x{:}\tau_1\) to \(\Gamma\) with its old \(x\) dropped and the new one added, and induction on \(e\) leaves the context free to do that.

Termination is the closed case: \(\Gamma\) and \(\gamma\) empty, and \(e[\,] = e\). Print Assumptions confirms nothing was assumed.

2. Types as sets, terms as functions

That took a whole section. A small-step semantics is a rewrite system, so it is potentially non-terminating by construction, and termination has to be fought for. A denotational semantics interprets each term as a function, and functions are total: termination comes for free. For STLC, with no loops and no recursion, this is the easiest case of denotational semantics all semester. Compare IMP, where everything was easy until \(\mathsf{while}\).

The plan, as for IMP: interpret compositionally, by recursion on the syntax, each operation of the language as an operation on the semantic side. The difference is that STLC has types, so the first question is what set a term's meaning lives in. Types become sets, contexts become sets, and terms become functions.

Types as sets

\[ [\![\mathsf{int}]\!] = \mathbb{Z} \qquad\qquad [\![\mathsf{bool}]\!] = \{\mathsf{true}, \mathsf{false}\} \]
\[ [\![\tau_1 \to \tau_2]\!] = [\![\tau_2]\!]^{[\![\tau_1]\!]} = [\![\tau_1]\!] \to [\![\tau_2]\!] \quad \text{(the set of functions)} \]

The exponential notation is the cardinality: there are \(2^n\) bit strings of length \(n\), the functions from an \(n\)-element set to the Booleans.

The lecture's other types: union or disjoint union?

With products and sums, \([\![1]\!]\) is a one-element set, \([\![\tau_1 \times \tau_2]\!]\) is the Cartesian product, and \([\![0]\!]\) is the empty set. For \([\![\tau_1 + \tau_2]\!]\) the room's first answer was the union. The test: \(1 + 1\) should be the Booleans, but \(\{*\} \cup \{*\} = \{*\}\) has one element. A sum value is \(\mathsf{in}_1\) or \(\mathsf{in}_2\), and \(\mathsf{case}\) tells them apart, so the semantics needs the tag too: the disjoint union

\[ A \uplus B = \{(1, a) \mid a \in A\} \cup \{(2, b) \mid b \in B\}, \qquad \{*\} \uplus \{*\} = \{(1, *), (2, *)\}. \]

On finite sets, \(1\), \(\times\), \(+\) and \(\to\) then match their arithmetic exactly. In set theory membership and union are basic; in a typed language, disjoint union and typing are.

Contexts as sets

A context is a list of typed variables, so its meaning is a product, a value for each variable:

\[ [\![\cdot]\!] = \{*\} \qquad\qquad [\![\Gamma, x{:}\tau]\!] = [\![\Gamma]\!] \times [\![\tau]\!] \]

An element \(\gamma \in [\![\Gamma]\!]\) gives a value for every variable in \(\Gamma\): the semantic version of a closing substitution. Shadowing is not an issue: by α-equivalence all variables are different.

In Rocq, \([\![\tau]\!]\) and \([\![\Gamma]\!]\) are Rocq types, by recursion on \(\tau\) and on \(\Gamma\).

Terms as functions

For \(\Gamma \vdash e : \tau\), the meaning of \(e\) is a function from values of its free variables to a value of its type:

\[ [\![e]\!] : [\![\Gamma]\!] \to [\![\tau]\!] \]

A closed term is a function from the one-element set, so it picks out one element \([\![e]\!](*) \in [\![\tau]\!]\). This is the right way to read λ-calculus notation: it looks like you are writing down elements, but because of the variables you are writing down functions. One clause per typing rule:

\[ [\![x]\!]\,\gamma = \gamma(x) \]
\[ [\![e_1\, e_2]\!]\,\gamma = ([\![e_1]\!]\,\gamma)\,([\![e_2]\!]\,\gamma) \]
\[ [\![\lambda x{:}\tau_1.\, e]\!]\,\gamma = z \mapsto [\![e]\!]\,(\gamma, x \mapsto z) \]
\[ [\![n]\!]\,\gamma = n \qquad [\![e_1 + e_2]\!]\,\gamma = [\![e_1]\!]\,\gamma + [\![e_2]\!]\,\gamma \qquad [\![\mathsf{true}]\!]\,\gamma = \mathsf{true} \]
\[ [\![\mathsf{if}\ e\ \mathsf{then}\ e_1\ \mathsf{else}\ e_2]\!]\,\gamma = \begin{cases} [\![e_1]\!]\,\gamma & [\![e]\!]\,\gamma = \mathsf{true} \\ [\![e_2]\!]\,\gamma & [\![e]\!]\,\gamma = \mathsf{false} \end{cases} \]

Application looks like applying a function to an argument, but it is an operation on two functions of \(\gamma\). In IMP the environment was threaded through, in and out, because assignment changed it; here variables are constants, and \(\gamma\) is simply copied to every subterm. The λ clause is currying: one argument moves from the tuple of inputs into the returned function. And "\(\mathsf{true}\) means \(\mathsf{true}\)" is as silly as it looks; denotational semantics gets silly at the base types.

In Rocq, \([\![e]\!]\) is defined on a typing derivation, so the derivation is data: deriv is the typing relation again, in Type, with the variable rule pointing at \(x\)'s position in \(\Gamma\). Then \([\![e]\!]\) is a Rocq function, and Compute runs it.

\(\gamma(x)\) reads \(x\)\u2019s value out of \(\gamma\) by following its position, and \([\![e]\!]\) is the six clauses above, one per rule.

Two closed examples, then an open one. For \(y{:}\mathsf{int}, x{:}\mathsf{int} \vdash \mathsf{if}\ \mathsf{true}\ \mathsf{then}\ x\ \mathsf{else}\ y\), an element of \([\![\Gamma]\!]\) is \(((*, 10), 20)\): the innermost pair is \(x\), the outer one \(y\), in the order the context lists them.

The open term and its derivation; there steps past \(y\) to reach \(x\). Running it on \(((*, 10), 20)\) gives \(10\), the value of \(x\).

3. Soundness and adequacy

Look at the two semantics side by side. The denotations at each type look like the closed values of that type, except at function type, where a closed value is a λ with some body and a denotation is a mathematical function. Operationally the meaning of a term is the value it reduces to; denotationally the element is built directly, by a total function, so there is no question whether it exists. The operational semantics only runs closed terms; the denotational one treats open terms as the general case.

What is the relationship? Two theorems, proved about every denotational semantics.

Soundness

\[ \textbf{Theorem (soundness).}\quad \text{If } e \longrightarrow^* v \text{ then } [\![e]\!](*) = [\![v]\!](*). \]

The meaning is an invariant of reduction. An operational purist reads the denotational semantics as a device that turns reductions into equalities. By induction on the run, from the one-step lemma: if \(e \longrightarrow e'\) then \([\![e]\!] = [\![e']\!]\), one case per step rule. Two of the cases:

\[ [\![\mathsf{if}\ \mathsf{true}\ \mathsf{then}\ e_1\ \mathsf{else}\ e_2]\!]\,\gamma \;=\; \class{hl-blue}{\bbox[#eef1f6,2pt]{[\![e_1]\!]\,\gamma}} \]

Two functions are equal when they agree on every \(\gamma\). Unfold the if clause: \([\![\mathsf{true}]\!]\,\gamma = \mathsf{true}\), so the first branch.

\[ [\![E[\mathsf{if}\ \mathsf{true}\ \mathsf{then}\ e_1\ \mathsf{else}\ e_2]]\!]\,\gamma \;=\; ([\![E]\!]\,\gamma)\,([\![\mathsf{if}\ \mathsf{true}\ \ldots]\!]\,\gamma) \;=\; ([\![E]\!]\,\gamma)\,([\![e_1]\!]\,\gamma) \;=\; [\![E[e_1]]\!]\,\gamma \]

Adequacy

Soundness goes the wrong way to give termination. The converse is not called completeness but adequacy, because in general it holds only at the simple types: with loops it fails at higher types, for computability reasons. Here it is at the Booleans, where a denotation is a value:

\[ \textbf{Theorem (adequacy at } \mathsf{bool}\textbf{).}\quad \text{If } \vdash e : \mathsf{bool} \text{ then } e \longrightarrow^* [\![e]\!](*). \]

The same statement holds at \(\mathsf{int}\), and at every type without a function in it. It cannot hold at \(\tau_1 \to \tau_2\): \(e\) reduces to a λ, not to a mathematical function. Adequacy at \(\mathsf{bool}\) alone proves every Boolean program terminates, and it makes the denotational semantics a tool: compute the meaning, with whatever mathematical shortcuts you like, instead of running the call-by-value steps.

The statement in Rocq, with the Boolean denotation turned back into a term. The proof is left out; it is the fundamental theorem of the relation defined next.

How to prove it? Induction on the typing derivation of a Boolean term runs into subterms of every type, open ones included. You know what time it is. The logical relation is now binary, between a closed value and an element of \([\![\tau]\!]\):

\[ n \approx^{\mathcal{V}}_{\mathsf{int}} m \iff n = m \qquad\qquad b \approx^{\mathcal{V}}_{\mathsf{bool}} b' \iff b = b' \]
\[ v \approx^{\mathcal{V}}_{\tau_1 \to \tau_2} f \iff \forall v' \approx^{\mathcal{V}}_{\tau_1} x.\ v\, v' \approx^{\mathcal{E}}_{\tau_2} f(x) \]
\[ e \approx^{\mathcal{E}}_\tau x \iff e \longrightarrow^* v \text{ and } v \approx^{\mathcal{V}}_\tau x \]

At \(\mathsf{int}\) and \(\mathsf{bool}\) the value and the denotation are the same thing, which is why "\(n = m\)" makes sense. The function clause is Part 1's, with the denotation \(f\) riding along. The fundamental theorem for this relation, "if \(\Gamma \vdash e : \tau\) then \(e[\gamma] \approx^{\mathcal{E}}_\tau [\![e]\!]\,\gamma\) for related \(\gamma\)", is proved exactly as in Part 1, and adequacy is its closed Boolean case. In Rocq the relation is defined and the theorem is stated; the proof is Part 1 again.
