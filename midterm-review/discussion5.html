Denotational semantics of IMP

Interpret IMP programs as functions, model divergence with partiality, and derive while from finite approximations.

IMP and its big-step semantics, followed by the denotational semantics from §3 of Kozen's CS 6110 Lecture 18 notes.

The runnable blocks form one continuous Rocq document.

  • Part 2 Partiality with option.

Syntax

\[ \begin{aligned} a &::= n \mid x \mid a_0 + a_1 \mid a_0 * a_1 \mid a_0 - a_1 \\ b &::= \mathsf{true} \mid \mathsf{false} \mid a_0 = a_1 \mid a_0 \le a_1 \mid b_0 \lor b_1 \mid b_0 \land b_1 \mid \lnot b \\ c &::= \mathsf{skip} \mid x := a \mid c_0 ; c_1 \mid \mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 \mid \mathsf{while}\ b\ \mathsf{do}\ c \end{aligned} \]

Concrete syntax. const n is the number \(n\) and var x is the variable \(x\), as expressions. ⊕, ⊗ and ⊖ are \(+\), \(*\) and \(-\) in the language, so they can't be confused with +, * and - on integers. In the same way, TRUE and FALSE are the Boolean expressions, and true and false are Rocq's Boolean values.

Environments

\(\sigma : \mathit{Var} \to \mathbb{Z}\), total. \(\sigma[x \mapsto n]\) is \(\sigma\), except that \(x\) now holds \(n\):

\[ \sigma[x \mapsto n](y) = \begin{cases} n & y = x \\ \sigma(y) & \text{otherwise} \end{cases} \]

Part 1: \(\mathcal{A}[\![a]\!]\) and \(\mathcal{B}[\![b]\!]\)

\[ \mathcal{A}[\![a]\!] : \mathit{Env} \to \mathbb{Z} \qquad\qquad \mathcal{B}[\![b]\!] : \mathit{Env} \to \mathbf{2} \]

In the \(\oplus\) line, \(\oplus\) on the left is \(+\) in the language, and \(+\) on the right is addition of integers. The notes write \(+\) for both.

Examples

With \(\sigma_0 = \{X \mapsto 3, Y \mapsto 2\}\): \(\mathcal{A}[\![(X + Y) * X]\!]\sigma_0 = 15\) and \(\mathcal{B}[\![\lnot(X = 0)]\!]\sigma_0 = \mathsf{true}\).

Part 2: Partiality with option

A partial function from \(D\) to \(E\) has no answer for some inputs. A Rocq function must always return an answer, so we make "no answer" one of the possible answers. The type option E has two kinds of values:

valuemeaning
\(\mathsf{Some}\ e\)an answer, \(e : E\)
\(\mathsf{None}\)no answer

A partial function from \(D\) to \(E\) is then a total function \(D \to \mathsf{option}\ E\). (The notes write \(E_\bot\) for \(\mathsf{option}\ E\), and \(\bot\) for \(\mathsf{None}\).) For example, dividing by 0 has no answer:

Part 3: \(\mathcal{C}[\![c]\!]\) and the base cases

Run a command \(c\) from \(\sigma\). Either it stops, in some environment \(\sigma'\), or it runs forever (like WHILE TRUE DO skip END). So the meaning of \(c\) is a partial map from \(\mathit{Env}\) to \(\mathit{Env}\):

\[ \mathcal{C}[\![c]\!] : \mathit{Env} \to \mathsf{option}\ \mathit{Env} \qquad \begin{aligned} \mathcal{C}[\![c]\!]\sigma &= \mathsf{Some}\ \sigma' && c \text{, run from } \sigma \text{, stops in } \sigma' \\ \mathcal{C}[\![c]\!]\sigma &= \mathsf{None} && c \text{, run from } \sigma \text{, runs forever} \end{aligned} \]

The base cases:

\[ \begin{aligned} \mathcal{C}[\![\mathsf{skip}]\!]\sigma &= \mathsf{Some}\ \sigma \\ \mathcal{C}[\![x := a]\!]\sigma &= \mathsf{Some}\ \sigma[x \mapsto \mathcal{A}[\![a]\!]\sigma] \\ \mathcal{C}[\![\mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1]\!]\sigma &= \text{if } \mathcal{B}[\![b]\!]\sigma \text{ then } \mathcal{C}[\![c_0]\!]\sigma \text{ else } \mathcal{C}[\![c_1]\!]\sigma \end{aligned} \]

skip and := always stop, so they always give \(\mathsf{Some}\). if picks a branch and then does whatever that branch does: if the branch runs forever, so does the if.

So none of these ever gives \(\mathsf{None}\). Only loops can run forever. But loops are coming, and sequencing has to be ready for them.

Part 4: Sequencing

Take \(c_1 ; c_2 ; c_3\). Each piece has a meaning

\[ \mathcal{C}[\![c_1]\!],\ \mathcal{C}[\![c_2]\!],\ \mathcal{C}[\![c_3]\!] : \mathit{Env} \to \mathsf{option}\ \mathit{Env} \]

and we want to put them together. For ordinary functions we would just compose them: \(\mathcal{C}[\![c_2]\!](\mathcal{C}[\![c_1]\!]\sigma)\). But that doesn't type-check: \(\mathcal{C}[\![c_1]\!]\sigma\) is an \(\mathsf{option}\ \mathit{Env}\), and \(\mathcal{C}[\![c_2]\!]\) wants an \(\mathit{Env}\).

So look at the two cases for \(\mathcal{C}[\![c_1]\!]\sigma\):

  • \(\mathsf{None}\): \(c_1\) runs forever. There is no environment to run \(c_2\) on, so the whole program runs forever. The answer is \(\mathsf{None}\).
  • \(\mathsf{Some}\ \sigma_1\): \(c_1\) stopped in \(\sigma_1\), so run \(c_2\) from there: \(\mathcal{C}[\![c_2]\!]\sigma_1\).

How do we define composition then? If

\[ \mathcal{C}[\![c_1]\!] : \mathit{Env} \to \mathsf{option}\ \mathit{Env} \qquad\text{and}\qquad \mathcal{C}[\![c_2]\!] : \mathit{Env} \to \mathsf{option}\ \mathit{Env}, \]

we can run \(\mathcal{C}[\![c_1]\!]\), and \(\mathcal{C}[\![c_2]\!]\) needs to take the output of this. So we define \(\mathcal{C}[\![c_2]\!]^\dagger\), the lift operation.

This case analysis is the Kleisli lift from lecture:

\[ f^\dagger : (D \to E_\bot) \to (D_\bot \to E_\bot) \qquad\qquad f^\dagger\,\mathsf{None} = \mathsf{None} \qquad f^\dagger\,(\mathsf{Some}\ x) = f\,x \]

\(f\) only accepts an environment; \(f^\dagger\) also accepts \(\mathsf{None}\), and passes it on. Sequencing, as in the notes:

\[ \mathcal{C}[\![c_1 ; c_2]\!]\sigma = \mathcal{C}[\![c_2]\!]^\dagger(\mathcal{C}[\![c_1]\!]\sigma) \]

For longer programs this nests inside out: \(c_1 ; c_2 ; c_3\) is \(\mathcal{C}[\![c_3]\!]^\dagger(\mathcal{C}[\![c_2]\!]^\dagger(\mathcal{C}[\![c_1]\!]\sigma))\), where \(c_3\) is written first but runs last. So we give the environment in the middle a name. Writing \(\mathcal{C}[\![c_2]\!]\) as \(\lambda\sigma'.\ \mathcal{C}[\![c_2]\!]\sigma'\) changes nothing:

\[ \mathcal{C}[\![c_2]\!]^\dagger(\mathcal{C}[\![c_1]\!]\sigma) \;=\; (\lambda\sigma'.\ \mathcal{C}[\![c_2]\!]\sigma')^\dagger(\mathcal{C}[\![c_1]\!]\sigma) \;=:\; \sigma' \leftarrow \mathcal{C}[\![c_1]\!]\sigma\ ;\ \mathcal{C}[\![c_2]\!]\sigma' \]

In general,

\[ \sigma' \leftarrow m\ ;\ \mathit{rest} \quad\text{means}\quad (\lambda\sigma'.\ \mathit{rest})^\dagger\ m. \]

Read it as: "run \(m\). If it stops, call the result \(\sigma'\) and go on with \(\mathit{rest}\). If it doesn't, neither does the whole thing." The two equations for \(\dagger\) become the two rules for computing with it:

\[ (\sigma' \leftarrow \mathsf{Some}\ \tau\ ;\ \mathit{rest}) = \mathit{rest}[\tau/\sigma'] \qquad\qquad (\sigma' \leftarrow \mathsf{None}\ ;\ \mathit{rest}) = \mathsf{None} \]

Example. The two-command program \(X := 1 ;\ Y := X + 1\), run from any \(\sigma\). Each step uses one line of \(\mathcal{C}[\![\cdot]\!]\) or one rule for the arrow:

\[ \begin{aligned} &\mathcal{C}[\![X := 1 ;\ Y := X + 1]\!]\sigma \\ &= \mathcal{C}[\![Y := X + 1]\!]^\dagger(\mathcal{C}[\![X := 1]\!]\sigma) && \text{sequencing, as in the notes} \\ &= \sigma' \leftarrow \mathcal{C}[\![X := 1]\!]\sigma\ ;\ \mathcal{C}[\![Y := X + 1]\!]\sigma' && \text{the same, with the arrow} \\ &= \sigma' \leftarrow \mathsf{Some}\ \sigma[X \mapsto 1]\ ;\ \mathcal{C}[\![Y := X + 1]\!]\sigma' && := \text{ line} \\ &= \mathcal{C}[\![Y := X + 1]\!](\sigma[X \mapsto 1]) && \text{arrow on } \mathsf{Some} \\ &= \mathsf{Some}\ \sigma[X \mapsto 1][Y \mapsto 2] && := \text{ line, since } \mathcal{A}[\![X + 1]\!](\sigma[X \mapsto 1]) = 2 \end{aligned} \]

Surprise. We have secretly just met one of the fundamental concepts of programming languages: a monad. The type former \(\mathsf{option}\), the map \(\mathsf{Some}\) (which is \(\mathcal{C}[\![\mathsf{skip}]\!]\)), and the lift \(\dagger\) are exactly the data of one, and the arrow syntax is the standard way to program with any monad. The definition is at the end of this note.

Here is all of \(\mathcal{C}[\![\cdot]\!]\). The \(;\) line is the notes' \(\mathcal{C}[\![c_1]\!]^\dagger(\mathcal{C}[\![c_0]\!]\sigma)\), written with the arrow. The while line is a placeholder: for now every loop means \(\mathsf{None}\), which is the notes' first approximation \(W_0 = \lambda\sigma.\ \bot\). It gets replaced when we do while.

A three-command program

\(\mathsf{Max}(x, y, r)\) compares \(x\) and \(y\), and stores the larger one in \(r\). Its denotation, by the if and := lines of \(\mathcal{C}[\![\cdot]\!]\):

\[ \mathcal{C}[\![\mathsf{Max}(x, y, r)]\!]\sigma = \begin{cases} \mathsf{Some}\ \sigma[r \mapsto \sigma(y)] & \sigma(x) \le \sigma(y) \\ \mathsf{Some}\ \sigma[r \mapsto \sigma(x)] & \text{otherwise} \end{cases} \]

Using the sequencing line twice, the meaning of \(c_1 ; c_2 ; c_3\) is

\[ \begin{aligned} &\sigma_1 \leftarrow \mathcal{C}[\![c_1]\!]\sigma_{\mathit{start}}\ ; \\ &\sigma_2 \leftarrow \mathcal{C}[\![c_2]\!]\sigma_1\ ; \\ &\sigma_3 \leftarrow \mathcal{C}[\![c_3]\!]\sigma_2\ ; \\ &\mathsf{Some}\ \sigma_3 \end{aligned} \]

(The last two lines could just be \(\mathcal{C}[\![c_3]\!]\sigma_2\): running \(c_3\) and then stopping where it stopped is the same as running \(c_3\).)

To compute it, we only need the two rules for the arrow:

\[ (\sigma' \leftarrow \mathsf{Some}\ \tau\ ;\ \mathit{rest}) = \mathit{rest}[\tau/\sigma'] \qquad\qquad (\sigma' \leftarrow \mathsf{None}\ ;\ \mathit{rest}) = \mathsf{None} \]

Write \(\tau_1 = \sigma_{\mathit{start}}[X \mapsto 3]\), \(\tau_2 = \tau_1[Y \mapsto 4]\), \(\tau_3 = \tau_2[R \mapsto 4]\).

\[ \begin{aligned} &\mathcal{C}[\![c_1 ; c_2 ; c_3]\!]\sigma_{\mathit{start}} \\ &= \sigma_1 \leftarrow \mathcal{C}[\![X := 3]\!]\sigma_{\mathit{start}} ;\ \sigma_2 \leftarrow \mathcal{C}[\![Y := 4]\!]\sigma_1 ;\ \sigma_3 \leftarrow \mathcal{C}[\![\mathsf{Max}(X,Y,R)]\!]\sigma_2 ;\ \mathsf{Some}\ \sigma_3 && \text{sequencing twice, fill in } c_1, c_2, c_3 \\ &= \sigma_1 \leftarrow \mathsf{Some}\ \tau_1 ;\ \sigma_2 \leftarrow \mathcal{C}[\![Y := 4]\!]\sigma_1 ;\ \sigma_3 \leftarrow \mathcal{C}[\![\mathsf{Max}(X,Y,R)]\!]\sigma_2 ;\ \mathsf{Some}\ \sigma_3 && := \text{ line} \\ &= \sigma_2 \leftarrow \mathcal{C}[\![Y := 4]\!]\tau_1 ;\ \sigma_3 \leftarrow \mathcal{C}[\![\mathsf{Max}(X,Y,R)]\!]\sigma_2 ;\ \mathsf{Some}\ \sigma_3 && \text{arrow on } \mathsf{Some}\ \tau_1 \\ &= \sigma_2 \leftarrow \mathsf{Some}\ \tau_2 ;\ \sigma_3 \leftarrow \mathcal{C}[\![\mathsf{Max}(X,Y,R)]\!]\sigma_2 ;\ \mathsf{Some}\ \sigma_3 && := \text{ line} \\ &= \sigma_3 \leftarrow \mathcal{C}[\![\mathsf{Max}(X,Y,R)]\!]\tau_2 ;\ \mathsf{Some}\ \sigma_3 && \text{arrow on } \mathsf{Some}\ \tau_2 \\ &= \sigma_3 \leftarrow \mathsf{Some}\ \tau_3 ;\ \mathsf{Some}\ \sigma_3 && \mathsf{Max}\text{: } \tau_2(X) = 3 \le 4 = \tau_2(Y) \\ &= \mathsf{Some}\ \tau_3 && \text{arrow on } \mathsf{Some}\ \tau_3 \end{aligned} \]

The environments:

\(X\)\(Y\)\(R\)
\(\sigma_{\mathit{start}}\)000
\(\tau_1 = \sigma_{\mathit{start}}[X \mapsto 3]\)300
\(\tau_2 = \tau_1[Y \mapsto 4]\)340
\(\tau_3 = \tau_2[R \mapsto 4]\) (\(3 \le 4\), so \(R\) gets \(Y\))344

Now make \(c_2\) a loop that never stops. \(\mathcal{C}[\![c_2^{\mathit{loop}}]\!]\sigma_1\) is \(\mathsf{None}\), so the arrow stops right there, and Max never runs:

\[ \begin{aligned} &\sigma_1 \leftarrow \mathcal{C}[\![c_1]\!]\sigma_{\mathit{start}}\ ; && \mathsf{Some}\ \sigma_1 \\ &\sigma_2 \leftarrow \mathcal{C}[\![c_2^{\mathit{loop}}]\!]\sigma_1\ ; && \mathsf{None}\text{: stop} \\ &\sigma_3 \leftarrow \mathcal{C}[\![c_3]\!]\sigma_2\ ; && \text{(never reached)} \\ &\mathsf{Some}\ \sigma_3 \end{aligned} \]

(\(\mathcal{C}[\![c_2^{\mathit{loop}}]\!]\) is \(\mathsf{None}\) for every \(\sigma\). That stays true once while has its real meaning.)

while: the approximations \(\mathcal{W}_n\)

For a loop \(\mathsf{while}\ b\ \mathsf{do}\ c\), the notes define approximations \(\mathcal{W}_n(b, c, \sigma)\):

\[ \begin{aligned} \mathcal{W}_0(b, c, \sigma) &= \mathsf{None} \\ \mathcal{W}_{n+1}(b, c, \sigma) &= \text{if } \mathcal{B}[\![b]\!]\sigma \text{ then } (\sigma' \leftarrow \mathcal{C}[\![c]\!]\sigma\ ;\ \mathcal{W}_n(b, c, \sigma')) \text{ else } \mathsf{Some}\ \sigma \end{aligned} \]

Think of \(\mathcal{W}_n\) as the loop with a timeout. It gives the loop's answer if the loop stops within \(n\) tests of \(b\) (so at most \(n - 1\) trips through the body), and \(\mathsf{None}\) otherwise. (The notes write \(\mathcal{W}_{n+1} = F\,\mathcal{W}_n\).)

The meaning of the loop is the limit of \(\mathcal{W}_0, \mathcal{W}_1, \mathcal{W}_2, \dots\) For each starting \(\sigma\), exactly one of two things happens:

  • \(\exists n.\ \mathcal{W}_n(b, c, \sigma) = \mathsf{Some}\ \tau\). Then \(\mathcal{W}_m(b, c, \sigma) = \mathsf{Some}\ \tau\) for every \(m \ge n\) (a longer timeout replays the same run), and

    • \[\mathcal{C}[\![\mathsf{while}\ b\ \mathsf{do}\ c]\!]\sigma = \mathsf{Some}\ \tau.\]

  • \(\forall n.\ \mathcal{W}_n(b, c, \sigma) = \mathsf{None}\). No timeout is long enough: the loop runs forever, and

    • \[\mathcal{C}[\![\mathsf{while}\ b\ \mathsf{do}\ c]\!]\sigma = \mathsf{None}.\]

Since an answer never changes once it appears, this limit is well defined; the notes call it the least upper bound of the \(\mathcal{W}_n\).

The ordering behind this. On answers, \(\mathit{Env}_\bot = \mathsf{option}\ \mathit{Env}\), the notes use the flat order ("knows at most as much as"):

\[ \mathsf{None} \sqsubseteq v \ \text{ for every } v \qquad\qquad \mathsf{Some}\ \tau \sqsubseteq \mathsf{Some}\ \tau' \iff \tau = \tau' \]

so \(\mathsf{None}\) is below everything, and two different answers are unrelated. On meanings, \(\mathit{Env} \to \mathsf{option}\ \mathit{Env}\), the order is pointwise:

\[ f \sqsubseteq g \;:\!\iff\; \forall \sigma.\ f\,\sigma \sqsubseteq g\,\sigma \;\iff\; \forall \sigma\,\tau.\ f\,\sigma = \mathsf{Some}\ \tau \implies g\,\sigma = \mathsf{Some}\ \tau \]

i.e. \(g\) answers wherever \(f\) does, with the same answer. (Seen as sets of pairs \((\sigma, \tau)\), this is just \(\subseteq\); compare §4 of the notes.) Then:

  • \(\mathcal{W}_0 = \lambda\sigma.\ \mathsf{None}\) is the least element: \(\mathcal{W}_0 \sqsubseteq f\) for every \(f\).
  • With \(F\,w = \lambda\sigma.\ \text{if } \mathcal{B}[\![b]\!]\sigma \text{ then } (\sigma' \leftarrow \mathcal{C}[\![c]\!]\sigma\ ;\ w\,\sigma') \text{ else } \mathsf{Some}\ \sigma\), we have \(\mathcal{W}_{n+1} = F\,\mathcal{W}_n\), and \(F\) is monotone (\(f \sqsubseteq g \implies F\,f \sqsubseteq F\,g\)), so

    • \[\mathcal{W}_0 \sqsubseteq \mathcal{W}_1 \sqsubseteq \mathcal{W}_2 \sqsubseteq \cdots \quad\text{(a chain).}\]

  • Least upper bounds of chains are taken pointwise:

    • \[\Big(\textstyle\bigsqcup_n \mathcal{W}_n\Big)\sigma = \begin{cases} \mathsf{Some}\ \tau & \text{if } \exists n.\ \mathcal{W}_n\,\sigma = \mathsf{Some}\ \tau \\ \mathsf{None} & \text{if } \forall n.\ \mathcal{W}_n\,\sigma = \mathsf{None} \end{cases}\] which is exactly the two cases above.

  • Every chain in \(\mathit{Env} \to \mathsf{option}\ \mathit{Env}\) has a least upper bound (it is a chain-complete partial order, a CPO), and \(F\) is continuous: \(F(\bigsqcup_n w_n) = \bigsqcup_n F\,w_n\). These are the two facts the notes need to extend their fixed-point theorem from \(\subseteq\) to CPOs. It gives

    • \[\mathcal{C}[\![\mathsf{while}\ b\ \mathsf{do}\ c]\!] = \textstyle\bigsqcup_n \mathcal{W}_n = \mathsf{fix}\ F,\] the least solution of \(W = F\,W\).

In Rocq, W takes the meanings bb \(= \mathcal{B}[\![b]\!]\) and cc \(= \mathcal{C}[\![c]\!]\) instead of \(b\) and \(c\), so that the while line of \(\mathcal{C}[\![\cdot]\!]\) can use it later. We write 𝒲 n (b, c, σ) for W ℬ⟦b⟧ 𝒞⟦c⟧ n σ.

\(\mathcal{W}_n\) on an example

The loop \(\mathsf{while}\ \lnot(X = 2)\ \mathsf{do}\ X := X + 1\) counts \(X\) up until it hits 2.

Write \(\rho_k\) for \(\sigma_{X0}\) with \(X\) set to \(k\), so the body takes \(\rho_k\) to \(\rho_{k+1}\): \(\mathcal{C}[\![X := X + 1]\!]\rho_k = \mathsf{Some}\ \rho_{k+1}\). Unfolding \(\mathcal{W}_3\) from \(\rho_0\):

\[ \begin{aligned} \mathcal{W}_3(b, c, \rho_0) &= \text{if } \mathcal{B}[\![b]\!]\rho_0 \text{ then } (\sigma' \leftarrow \mathcal{C}[\![c]\!]\rho_0\ ;\ \mathcal{W}_2(b, c, \sigma')) \text{ else } \mathsf{Some}\ \rho_0 \\ &= \sigma' \leftarrow \mathsf{Some}\ \rho_1\ ;\ \mathcal{W}_2(b, c, \sigma') && X = 0 \ne 2\text{: test true, run } c \\ &= \mathcal{W}_2(b, c, \rho_1) && \text{arrow on } \mathsf{Some}\ \rho_1 \\ &= \mathcal{W}_1(b, c, \rho_2) && X = 1 \ne 2\text{: the same two steps} \\ &= \mathsf{Some}\ \rho_2 && X = 2\text{: test false, stop} \end{aligned} \]

One step less runs out of time just before the last test:

\[ \mathcal{W}_2(b, c, \rho_0) = \mathcal{W}_1(b, c, \rho_1) = \mathcal{W}_0(b, c, \rho_2) = \mathsf{None} \]

Started with \(X = 0\), it tests \(X = 2\) three times (\(X = 0, 1, 2\)) and goes through the body twice. So the answer first appears at \(\mathcal{W}_3\), and after that it never changes. Started with \(X = 5\), it counts \(5, 6, 7, \dots\) and never hits 2. Every \(\mathcal{W}_n\) gives \(\mathsf{None}\): no timeout is long enough.

Part 5: Equational reasoning

Meanings are functions, so "same meaning" is an equation, and we can reason about programs by calculation, as in algebra. There are three layers: expressions, commands without loops, and loops.

Expressions: plain algebra

\[ a \equiv_a a' \;:\!\iff\; \forall\sigma.\ \mathcal{A}[\![a]\!]\sigma = \mathcal{A}[\![a']\!]\sigma \qquad\qquad b \equiv_b b' \;:\!\iff\; \forall\sigma.\ \mathcal{B}[\![b]\!]\sigma = \mathcal{B}[\![b']\!]\sigma \]

\(\mathcal{A}\) and \(\mathcal{B}\) are total, so we get the usual laws of \(\mathbb{Z}\) and of booleans:

\[ a + 0 \equiv_a a \qquad a_0 + a_1 \equiv_a a_1 + a_0 \qquad a * 1 \equiv_a a \qquad \lnot\lnot b \equiv_b b \qquad \lnot(b_0 \land b_1) \equiv_b \lnot b_0 \lor \lnot b_1 \qquad (a = a) \equiv_b \mathsf{true} \]

Constant folding lives here: \(\mathsf{cfold} : \mathit{AExp} \to \mathit{AExp}\), \(\mathsf{cfold}(Y + (2 * 3)) = Y + 6\), and \(\forall a.\ \mathsf{cfold}\ a \equiv_a a\) (induction on \(a\)).

Commands without loops: algebra with partiality

\[ c \equiv c' \;:\!\iff\; \forall\sigma.\ \mathcal{C}[\![c]\!]\sigma = \mathcal{C}[\![c']\!]\sigma \qquad \text{(both run forever, or both stop in the same environment)} \]

Expression laws carry over:

\[ a \equiv_a a' \implies x := a \;\equiv\; x := a' \quad (\text{e.g. } x := a \equiv x := \mathsf{cfold}\ a) \qquad\qquad b \equiv_b b' \implies \mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 \;\equiv\; \mathsf{if}\ b'\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 \]

Laws (unfold \(\mathcal{C}[\![\cdot]\!]\), case on \(\mathcal{B}[\![b]\!]\sigma\) or on whether \(\mathcal{C}[\![c_0]\!]\sigma\) is \(\mathsf{Some}\) or \(\mathsf{None}\)):

\[ \begin{aligned} \mathsf{if}\ \mathsf{true}\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 &\equiv c_0 \\ \mathsf{skip} ; c &\equiv c \\ c ; \mathsf{skip} &\equiv c \\ (c_0 ; c_1) ; c_2 &\equiv c_0 ; (c_1 ; c_2) \\ \mathsf{if}\ b\ \mathsf{then}\ c\ \mathsf{else}\ c &\equiv c \\ \mathsf{if}\ \lnot b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 &\equiv \mathsf{if}\ b\ \mathsf{then}\ c_1\ \mathsf{else}\ c_0 \\ \mathsf{if}\ b\ \mathsf{then}\ (c_0 ; c)\ \mathsf{else}\ (c_1 ; c) &\equiv (\mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1) ; c \end{aligned} \]

Congruence (\(\mathcal{C}[\![c_0 ; c_1]\!]\) and \(\mathcal{C}[\![\mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1]\!]\) only use \(\mathcal{B}[\![b]\!]\), \(\mathcal{C}[\![c_0]\!]\), \(\mathcal{C}[\![c_1]\!]\)):

\[ \frac{c_0 \equiv c_0'}{c_0 ; c_1 \equiv c_0' ; c_1} \qquad \frac{c_1 \equiv c_1'}{c_0 ; c_1 \equiv c_0 ; c_1'} \qquad \frac{c_0 \equiv c_0' \quad c_1 \equiv c_1'}{\mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1 \equiv \mathsf{if}\ b\ \mathsf{then}\ c_0'\ \mathsf{else}\ c_1'} \]

So we can calculate, and each step is a rewrite a compiler may use:

\[ \begin{aligned} &X := 3 ;\ \mathsf{if}\ \mathsf{true}\ \mathsf{then}\ (\mathsf{skip} ; Y := 4)\ \mathsf{else}\ \mathsf{skip} \\ \equiv\ &X := 3 ;\ (\mathsf{skip} ; Y := 4) && \text{if-true law, inside } ; \\ \equiv\ &X := 3 ;\ Y := 4 && \mathsf{skip} ; c \equiv c\text{, inside } ; \end{aligned} \]

Loops: equations plus induction

With \(\mathcal{C}[\![\mathsf{while}\ b\ \mathsf{do}\ c]\!]\sigma\) the limit of \(\mathcal{W}_n(b, c, \sigma)\), some equations still hold:

\[ \begin{aligned} \mathsf{while}\ b\ \mathsf{do}\ c &\equiv \mathsf{if}\ b\ \mathsf{then}\ (c ; \mathsf{while}\ b\ \mathsf{do}\ c)\ \mathsf{else}\ \mathsf{skip} && \text{(the limit is a fixed point)} \\ \mathsf{while}\ \mathsf{false}\ \mathsf{do}\ c &\equiv \mathsf{skip} \\ c \equiv c' &\implies \mathsf{while}\ b\ \mathsf{do}\ c \equiv \mathsf{while}\ b\ \mathsf{do}\ c' && (\mathcal{W}_n \text{ only uses } \mathcal{C}[\![c]\!]) \end{aligned} \]

But equations alone cannot pin a loop down. For \(\mathsf{while}\ \mathsf{true}\ \mathsf{do}\ \mathsf{skip}\) the unrolling equation says \(W\sigma = W\sigma\), which every \(W\) satisfies. To show what a loop does, we need induction: on \(n\) (the \(\mathcal{W}_n\)), or on the data (\(P_1 \equiv P_2\) below needs induction on \(\sigma(X)\)).

What \(\equiv\) does not tell us

  1. Too strict. \(R := (X + Y) * (X + Y) \;\not\equiv\; T := X + Y ;\ R := T * T\), although both give the same \(R\); they differ at \(T\).
  2. A fact about the model. It says something about runs only if \(\langle c, \sigma\rangle \Downarrow \tau \iff \mathcal{C}[\![c]\!]\sigma = \mathsf{Some}\ \tau\) (Theorem 1 in the notes; not proved here), and cfold is correct in \(\mathbb{Z}\), not in 64-bit arithmetic.
  3. Language-specific. \(\mathsf{if}\ b\ \mathsf{then}\ c\ \mathsf{else}\ c \equiv c\) needs \(\mathcal{B}[\![b]\!]\sigma\) to always finish and to leave \(\sigma\) alone.
  4. No running time. See below.

Denotations forget running time

\[ \begin{aligned} P_1 &= \mathsf{if}\ 1 \le X\ \mathsf{then}\ X := 0\ \mathsf{else}\ \mathsf{skip} \\ P_2 &= \mathsf{while}\ 1 \le X\ \mathsf{do}\ X := X - 1 \\ \mathcal{C}[\![P_1]\!] = \mathcal{C}[\![P_2]\!] &= \lambda\sigma.\ \text{if } 1 \le \sigma(X) \text{ then } \mathsf{Some}\ \sigma[X \mapsto 0] \text{ else } \mathsf{Some}\ \sigma \end{aligned} \]

So \(P_1 \equiv P_2\), but \(P_1\) takes one step and \(P_2\) takes \(\sigma(X)\) trips through its loop.

Appendix on monads

A monad, presented as an extension system (also called a Kleisli triple), is

\[ T : \mathsf{Type} \to \mathsf{Type} \qquad\qquad \eta_A : A \to T\,A \qquad\qquad (-)^\dagger : (A \to T\,B) \to (T\,A \to T\,B) \]

satisfying three equations, for all \(f : A \to T\,B\) and \(g : B \to T\,C\):

\[ \begin{aligned} \eta_A^\dagger &= \mathrm{id}_{T A} \\ f^\dagger \circ \eta_A &= f \\ (g^\dagger \circ f)^\dagger &= g^\dagger \circ f^\dagger \end{aligned} \]

Read \(T\,A\) as "computations that produce an \(A\)", \(\eta\) as "produce this value and do nothing else", and \(f^\dagger\) as "run a computation, then continue with \(f\)". Often one writes \(\mathsf{bind}\ m\ f = f^\dagger\,m\) instead; it is the same data.

The syntax works for every monad. Define, exactly as for option,

\[ x \leftarrow m\ ;\ \mathit{rest} \;:=\; (\lambda x.\ \mathit{rest})^\dagger\ m \]

Then the three equations say:

\[ \begin{aligned} (x \leftarrow m\ ;\ \eta\,x) &= m \\ (x \leftarrow \eta\,a\ ;\ \mathit{rest}) &= \mathit{rest}[a/x] \\ (y \leftarrow (x \leftarrow m\ ;\ f\,x)\ ;\ g\,y) &= (x \leftarrow m\ ;\ y \leftarrow f\,x\ ;\ g\,y) \end{aligned} \]

Option is a monad

\[ T\,A = \mathsf{option}\ A \qquad \eta_A = \mathsf{Some} \qquad f^\dagger\,\mathsf{None} = \mathsf{None},\quad f^\dagger\,(\mathsf{Some}\ x) = f\,x \]

Each equation is checked by cases on whether the input is \(\mathsf{None}\) or \(\mathsf{Some}\ x\):

  • \(\eta^\dagger\) sends \(\mathsf{None} \mapsto \mathsf{None}\) and \(\mathsf{Some}\ x \mapsto \mathsf{Some}\ x\), so it is the identity.
  • \(f^\dagger(\mathsf{Some}\ x) = f\,x\) is the definition of \(\dagger\).
  • Both sides of the third equation send \(\mathsf{None}\) to \(\mathsf{None}\), and both send \(\mathsf{Some}\ x\) to \(g^\dagger(f\,x)\).

With \(\eta = \mathcal{C}[\![\mathsf{skip}]\!]\) and \(\mathcal{C}[\![c_0 ; c_1]\!] = \mathcal{C}[\![c_1]\!]^\dagger \circ \mathcal{C}[\![c_0]\!]\), the three equations are three program equivalences from Part 5:

\[ c ; \mathsf{skip} \equiv c \qquad\qquad \mathsf{skip} ; c \equiv c \qquad\qquad (c_0 ; c_1) ; c_2 \equiv c_0 ; (c_1 ; c_2) \]

Because the arrow syntax only uses \(\eta\) and \(\dagger\), the sequencing clause

\[ \mathcal{C}[\![c_0 ; c_1]\!]\sigma = \sigma' \leftarrow \mathcal{C}[\![c_0]\!]\sigma\ ;\ \mathcal{C}[\![c_1]\!]\sigma' \]

reads the same for every monad, and so do skip (\(\eta\,\sigma\)), assignment (\(\eta\,\sigma[x \mapsto \mathcal{A}[\![a]\!]\sigma]\)) and if. Changing \(T\) changes what kind of effect commands may have. For example, with \(T = \mathcal{P}\) a command may have several final environments; that is §4 of the notes, where \(\mathcal{C}[\![c]\!] : \mathit{Env} \to \mathcal{P}(\mathit{Env})\) is the same thing as a relation \([\![c]\!] \subseteq \mathit{Env} \times \mathit{Env}\), and \(\dagger\) becomes relational composition. (while needs more than a monad: an order on \(T\,\mathit{Env}\) in which the approximations \(\mathcal{W}_n\) have a least upper bound.)

The idea of structuring denotational semantics with monads is due to Moggi, Notions of computation and monads (1991).

Moggi's monadic metalanguage

Moggi's metalanguage is the simply typed λ-calculus extended with one type former \(T\) and two term formers, return and bind:

\[ \begin{aligned} A, B &::= \iota \mid 1 \mid A \times B \mid A \to B \mid T\,A \\ e &::= x \mid \langle\rangle \mid \langle e_1, e_2 \rangle \mid \pi_i\,e \mid \lambda x{:}A.\ e \mid e_1\,e_2 \mid \mathsf{ret}\ e \mid \mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ e_2 \end{aligned} \]

\[ \frac{\Gamma \vdash e : A}{\Gamma \vdash \mathsf{ret}\ e : T\,A} \qquad\qquad \frac{\Gamma \vdash e_1 : T\,A \qquad \Gamma, x{:}A \vdash e_2 : T\,B}{\Gamma \vdash \mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ e_2 : T\,B} \]

Besides the usual \(\beta\eta\) for \(\to\) and \(\times\), there are three equations, the monad laws again:

\[ \begin{aligned} \mathsf{let}\ x \Leftarrow \mathsf{ret}\ e\ \mathsf{in}\ e_2 &= e_2[e/x] \\ \mathsf{let}\ x \Leftarrow e\ \mathsf{in}\ \mathsf{ret}\ x &= e \\ \mathsf{let}\ y \Leftarrow (\mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ e_2)\ \mathsf{in}\ e_3 &= \mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ \mathsf{let}\ y \Leftarrow e_2\ \mathsf{in}\ e_3 \qquad (x \notin \mathrm{FV}(e_3)) \end{aligned} \]

Our arrow syntax is exactly this: \(x \leftarrow e_1\ ;\ e_2\) is \(\mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ e_2\), and \(\mathsf{ret}\) is \(\eta\). Only \(T\,A\) types can be sequenced; a plain \(A\) is a value, with no effect.

Semantics. Interpret \(T\) as a monad: \([\![T\,A]\!] = T\,[\![A]\!]\), \([\![\mathsf{ret}\ e]\!] = \eta \circ [\![e]\!]\), and, in sets,

\[ [\![\mathsf{let}\ x \Leftarrow e_1\ \mathsf{in}\ e_2]\!]\,\gamma \;=\; (\lambda a.\ [\![e_2]\!](\gamma, a))^\dagger\,([\![e_1]\!]\,\gamma). \]

\(e_2\) may use the variables in \(\Gamma\) as well as \(x\). In a general category this needs a strong monad, i.e. a map \(\Gamma \times T\,A \to T(\Gamma \times A)\); in sets every monad has one.

So this whole note is a program in the metalanguage with \(T = \mathsf{option}\): \(\mathcal{C}[\![c]\!] : \mathit{Env} \to T\,\mathit{Env}\), and

\[ \mathcal{C}[\![c_0 ; c_1]\!] = \lambda\sigma.\ \mathsf{let}\ \sigma' \Leftarrow \mathcal{C}[\![c_0]\!]\sigma\ \mathsf{in}\ \mathcal{C}[\![c_1]\!]\sigma' \qquad\qquad \mathcal{C}[\![\mathsf{skip}]\!] = \lambda\sigma.\ \mathsf{ret}\ \sigma. \]

Reading a function type \(A \to B\) of a call-by-value language as \(A \to T\,B\) is how Moggi uses the metalanguage to give semantics to effectful languages uniformly. References: Moggi, Computational lambda-calculus and monads (LICS 1989), and Notions of computation and monads (Information and Computation, 1991).

State and IO in the metalanguage

To use the metalanguage for a particular effect, pick the monad and add the operations of that effect as constants of \(T\) type.

State. For a set of states \(S\):

\[ T\,A = S \to A \times S \qquad \eta\,a = \lambda s.\ (a, s) \qquad f^\dagger\,m = \lambda s.\ \text{let } (x, s') = m\,s \text{ in } f\,x\,s' \]

with two operations, read the state and overwrite it:

\[ \mathsf{get} : T\,S, \quad \mathsf{get} = \lambda s.\ (s, s) \qquad\qquad \mathsf{put} : S \to T\,1, \quad \mathsf{put}\ s' = \lambda s.\ (\langle\rangle, s') \]

\(\dagger\) threads the state through: the second computation starts in the state the first one left behind. With \(S = \mathit{Env}\), IMP can be written so that the environment never appears in the sequencing clause. Use \(T\,A = \mathit{Env} \to \mathsf{option}(A \times \mathit{Env})\) (state and partiality; \(\mathsf{get}\) and \(\mathsf{put}\) as above, with their results wrapped in \(\mathsf{Some}\)) and give commands type \(T\,1\):

\[ \begin{aligned} \mathcal{C}[\![\mathsf{skip}]\!] &= \mathsf{ret}\ \langle\rangle \\ \mathcal{C}[\![x := a]\!] &= \mathsf{let}\ \sigma \Leftarrow \mathsf{get}\ \mathsf{in}\ \mathsf{put}\ \sigma[x \mapsto \mathcal{A}[\![a]\!]\sigma] \\ \mathcal{C}[\![c_0 ; c_1]\!] &= \mathsf{let}\ \_ \Leftarrow \mathcal{C}[\![c_0]\!]\ \mathsf{in}\ \mathcal{C}[\![c_1]\!] \\ \mathcal{C}[\![\mathsf{if}\ b\ \mathsf{then}\ c_0\ \mathsf{else}\ c_1]\!] &= \mathsf{let}\ \sigma \Leftarrow \mathsf{get}\ \mathsf{in}\ \text{if } \mathcal{B}[\![b]\!]\sigma \text{ then } \mathcal{C}[\![c_0]\!] \text{ else } \mathcal{C}[\![c_1]\!] \end{aligned} \]

Sequencing is now just "do \(c_0\), then \(c_1\)"; passing the environment along is the monad's job. Running \(\mathcal{C}[\![c]\!]\) from \(\sigma\) means applying it to \(\sigma\), which gives back \(\mathsf{Some}(\langle\rangle, \sigma')\) or \(\mathsf{None}\), the same information as before.

IO. For a language with \(\mathsf{print}\), use the writer monad with lists of strings, \(W = \mathsf{String}^*\):

\[ T\,A = A \times W \qquad \eta\,a = (a, [\,]) \qquad f^\dagger\,(x, w) = \text{let } (y, w') = f\,x \text{ in } (y, w \mathbin{+\!\!+} w') \qquad \mathsf{print} : \mathsf{String} \to T\,1,\quad \mathsf{print}\ s = (\langle\rangle, [s]) \]

\(\dagger\) appends the outputs in the order the program produced them.

In each case the arrow syntax, and the sequencing clause written with it, is unchanged: only \(T\), \(\eta\), \(\dagger\) and the operations change.
