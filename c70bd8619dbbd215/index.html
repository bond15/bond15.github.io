Sums appear in many languages. \(\tau_1 + \tau_2\) is Either[A, B] in Scala, Result<T, E> in Rust, and Either a b in Haskell. In each, \(\mathsf{in}_1\) and \(\mathsf{in}_2\) are Left and Right (Scala, Haskell) or Ok and Err (Rust).

For example, Rust's standard library defines enum Result<T, E> { Ok(T), Err(E) }. Here is a division that fails on zero, and a function that takes its result apart:

fn div(n: i32, d: i32) -> Result<i32, String> {
    if d == 0 { Err(String::from("divide by zero")) } else { Ok(n / d) }
}

fn describe(r: Result<i32, String>) -> String {
    match r {
        Ok(q) => format!("quotient {}", q),
        Err(msg) => msg,
    }
}

OCaml's standard library has the same type, called result: type ('a, 'b) result = Ok of 'a | Error of 'b. The same two functions:

let div n d = if d = 0 then Error "divide by zero" else Ok (n / d)

let describe r =
  match r with
  | Ok q -> "quotient " ^ string_of_int q
  | Error msg -> msg

In the lecture's terms, OCaml's div has type \(\mathsf{int} \to \mathsf{int} \to \mathsf{int} + \mathsf{string}\). Rust's takes both arguments at once, so its type is \(\mathsf{int} \times \mathsf{int} \to \mathsf{int} + \mathsf{string}\): the two are related by currying, from Part 2. In both, Ok is \(\mathsf{in}_1\), Err (or Error) is \(\mathsf{in}_2\), and describe's match is \(\mathsf{case}_+\).

\(\mathbf{0}\) has no introduction form, so it has no values, and a case on it has no branches: this is the lecture's \(\mathsf{case}_{\mathbf{0}}\ e\ \{\}\). From an impossible value, you can return anything.

2. Isomorphisms

Here are some equations from grade school, true for all numbers \(n\), \(m\) and \(k\):

\[ \begin{gathered} n \cdot 1 = n \qquad n + 0 = n \qquad n \cdot 0 = 0 \\ n \cdot m = m \cdot n \qquad 2 = 1 + 1 \\ n\,(m + k) = n m + n k \\ k^{n \cdot m} = (k^m)^n \end{gathered} \]

They work for types too. Read \(\cdot\) as \(\times\), \(+\) as \(+\), \(k^n\) as \(n \to k\) (a function picks one of \(k\) outputs for each of \(n\) inputs), and \(=\) as \(\cong\):

\[ \begin{gathered} \tau \times \mathbf{1} \cong \tau \qquad \tau + \mathbf{0} \cong \tau \qquad \tau \times \mathbf{0} \cong \mathbf{0} \\ \tau_1 \times \tau_2 \cong \tau_2 \times \tau_1 \qquad \mathsf{bool} \cong \mathbf{1} + \mathbf{1} \\ \tau_1 \times (\tau_2 + \tau_3) \cong \tau_1 \times \tau_2 + \tau_1 \times \tau_3 \\ (\tau_1 \times \tau_2 \to \tau_3) \cong (\tau_1 \to \tau_2 \to \tau_3) \end{gathered} \]

Two types are isomorphic, \(\tau_1 \cong \tau_2\), when there are programs \(f : \tau_1 \to \tau_2\) and \(g : \tau_2 \to \tau_1\) that undo each other, in both orders:

\[ \begin{aligned} &\text{retraction:} && \forall x{:}\tau_1.\; g\,(f\, x) = x && \text{(\(g\) undoes \(f\))} \\ &\text{section:} && \forall y{:}\tau_2.\; f\,(g\, y) = y && \text{(\(f\) undoes \(g\))} \end{aligned} \]

We say \(g\) is a retraction of \(f\) when the first holds, and a section of \(f\) when the second holds. As a picture, going around either loop does nothing:

Then \(\tau_1\) and \(\tau_2\) have the same values, with different names.

Each isomorphism below is a pair of programs \(f\) and \(g\) in the lecture's language. Try writing each program from its type before reading it. In Rocq, each pair sits in a module of its own, so every one can be called f and g; from outside, they are ProdUnit.f, Dist.g, and so on. In Rocq, the proofs that the two programs undo each other follow the same pattern: unfold iso into its two laws and split them; in each, cbv delta [f g] unfolds \(f\) and \(g\), putting in their programs, and cbv beta substitutes the argument (the β step); take the value apart, one case per way it can be built; then simpl runs the rest, and reflexivity sees that both sides are the same. Step through a proof to watch both sides become equal. The two exceptions: for \(\tau \times \mathbf{0} \cong \mathbf{0}\) there is nothing to compute, since no value can be built, and for curry the values are functions, so the proof first uses funext.

\(\tau \times \mathbf{0} \cong \mathbf{0}\)

Like \(n \cdot 0 = 0\). A pair would need a value of \(\mathbf{0}\), so there are no such pairs, and the proofs have no cases.

\(\tau_1 \times \tau_2 \cong \tau_2 \times \tau_1\)

Like \(n \cdot m = m \cdot n\). Both programs swap the pair, and swapping twice gives it back.

\[ f = \lambda p{:}\tau_1 \times \tau_2.\, (p.2, p.1) \]
\[ g : \tau_2 \times \tau_1 \to \tau_1 \times \tau_2 \]

\(\tau_1 \times (\tau_2 + \tau_3) \cong \tau_1 \times \tau_2 + \tau_1 \times \tau_3\)

Like \(n(m + k) = nm + nk\). A pair whose second part is "a \(\tau_2\) or a \(\tau_3\)" is the same as "a pair with a \(\tau_2\), or a pair with a \(\tau_3\)".

\[ f : \tau_1 \times (\tau_2 + \tau_3) \to \tau_1 \times \tau_2 + \tau_1 \times \tau_3 \]
\[ \begin{aligned} f &= \lambda p{:}\tau_1 \times (\tau_2 + \tau_3).\\ &\qquad \mathsf{case}_+\ p.2\ \{\mathsf{in}_1\ y \to \mathsf{in}_1\ (p.1, y) \\ &\qquad\qquad\quad\; \mid \mathsf{in}_2\ z \to \mathsf{in}_2\ (p.1, z)\} \end{aligned} \]

\((\tau_1 \times \tau_2 \to \tau_3) \cong (\tau_1 \to \tau_2 \to \tau_3)\)

Like \(c^{a \cdot b} = (c^b)^a\). A function of a pair is the same as a function that takes its two arguments one at a time. \(f\) is usually called \(\mathsf{curry}\), and \(g\) \(\mathsf{uncurry}\).

\[ f : (\tau_1 \times \tau_2 \to \tau_3) \to (\tau_1 \to \tau_2 \to \tau_3) \]
\[ f = \lambda h{:}\tau_1 \times \tau_2 \to \tau_3.\, \lambda x{:}\tau_1.\, \lambda y{:}\tau_2.\, h\ (x, y) \]
\[ g : (\tau_1 \to \tau_2 \to \tau_3) \to (\tau_1 \times \tau_2 \to \tau_3) \]
\[ g = \lambda k{:}\tau_1 \to \tau_2 \to \tau_3.\, \lambda p{:}\tau_1 \times \tau_2.\, k\ p.1\ p.2 \]

Here the values are functions, and two functions are equal when they agree on every input. Rocq can't prove that, so the code assumes it, as funext.

\(\mathsf{bool} \cong \mathbf{1} + \mathbf{1}\)

\[ f = \lambda b{:}\mathsf{bool}.\, \mathsf{if}\ b\ \mathsf{then}\ \mathsf{in}_1\ ()\ \mathsf{else}\ \mathsf{in}_2\ () \]

\(\mathsf{None}\) is \(\mathsf{in}_1\ ()\), and \(\mathsf{Some}\ x\) is \(\mathsf{in}_2\ x\): "nothing, or a \(\tau\)". Like \(\mathsf{bool}\), \(\mathsf{option}\) is Rocq's, not the lecture's, so it is taken apart with a Rocq match.

3. The Curry–Howard correspondence

Read a type as a proposition, and a program of that type as a proof of it: types as propositions. This is the Curry–Howard correspondence, between the simply typed λ-calculus and intuitionistic propositional logic:

Erase the terms from a typing rule and you get a rule of logic. From easiest to hardest: \(()\) proves \(\top\); a case on \(\mathbf{0}\) is “from false, anything”; a pair is a proof of \(\varphi \wedge \psi\) from a proof of each; a case is a proof by cases; a \(\lambda\) proves \(\varphi \Rightarrow \psi\) by assuming \(\varphi\) and proving \(\psi\); and application is modus ponens:

Curry–Howard–Lambek

The correspondence has a third corner. Our language, with \(\times\), \(+\), \(\mathbf{1}\), \(\mathbf{0}\) and \(\to\), is also the language of bicartesian closed categories (BCCCs): a type is an object, a program is a morphism (programs that are equal up to β and η are the same morphism), \(\times\) and \(+\) are the product and coproduct, \(\mathbf{1}\) and \(\mathbf{0}\) are the terminal and initial objects, and \(\to\) is the exponential. Lambek showed this for \(\times\), \(\mathbf{1}\) and \(\to\), the cartesian closed part. Together this is the Curry–Howard–Lambek correspondence:

These categories are always distributive: since \(\tau_1 \times -\) has a right adjoint, \(\tau_1 \to -\), it preserves coproducts and the initial object. So \(\tau_1 \times (\tau_2 + \tau_3) \cong \tau_1 \times \tau_2 + \tau_1 \times \tau_3\) and \(\tau \times \mathbf{0} \cong \mathbf{0}\) from Part 2 hold in every bicartesian closed category.

One proof, two readings

Take currying, \((\varphi \wedge \psi \Rightarrow \xi) \Rightarrow (\varphi \Rightarrow \psi \Rightarrow \xi)\). It has three assumptions, one for each \(\Rightarrow\) we prove by assuming its left side: \(\varphi \wedge \psi \Rightarrow \xi\), then \(\varphi\), then \(\psi\). Write \(\Delta\) for all three:

\[ \Delta = \varphi \wedge \psi \Rightarrow \xi,\ \varphi,\ \psi \]

A leaf with no line above it, such as \(\Delta \vdash \varphi\), uses one of the assumptions. Here is a proof tree using the rules above, built from the goal at the bottom up: each rule turns the goal below its line into the goals above it. Then the same tree becomes a typing derivation, again from the root up: each proposition turns into its type, and then the program that the rule builds appears beside it.

What about \(\forall\) and \(\exists\)?

Our logic is propositional: it has \(\top\), \(\bot\), \(\wedge\), \(\vee\) and \(\Rightarrow\), but no \(\forall x.\, \varphi(x)\) or \(\exists x.\, \varphi(x)\). A quantified proposition is about a value \(x\): the proposition \(\varphi(x)\) depends on \(x\). On the types side, that is a type that depends on a value, a dependent type. The simply typed λ-calculus has none: its types never mention programs.

Rocq is a dependent type theory, and has both. On the types side, \(\forall\) is the dependent function type \(\Pi\), and \(\exists\) is the dependent pair type \(\Sigma\):

A proof of \(\forall x{:}\tau.\, \varphi\) is a function that works for every \(x\), and using it at \(t\) proves \(\varphi\) for that \(t\). A proof of \(\exists x{:}\tau.\, \varphi\) is a witness with a proof that \(\varphi\) holds of it, and using it means taking the pair apart, without knowing which witness it was. \(\Sigma\) can do more: its projections read the witness back out, \(e.1\), and \(\exists\) has no rule for that.

The type of values from Discussion 6, { e : exp | value e }, is a \(\Sigma\) type: an expression together with a proof that it is a value. At Prop, Rocq writes \(\exists\) as exists x, φ x, which has only the case rule.

Excluded middle

Can you prove \(\varphi \vee \neg \varphi \)?

Here \(\neg \varphi \) is \(\varphi \Rightarrow \bot\), so as a type it is \(\varphi + (\varphi \to \mathbf{0})\). A program of this type would have to choose \(\mathsf{in}_1\) or \(\mathsf{in}_2\) without knowing anything about \(\varphi \): \(\mathsf{in}_1\) needs a proof of \(\varphi \), and \(\mathsf{in}_2\) needs a way to turn any proof of \(\varphi \) into a contradiction. There is no such program, so \(\varphi \vee \neg \varphi \) can't be proved this way. That is exactly what makes the logic intuitionistic.

But it can't be refuted either: its double negation, \(\neg\neg(\varphi \vee \neg \varphi )\), has a proof. Given \(h : \neg(\varphi \vee \neg \varphi )\), choose the right side; to show \(\neg \varphi \), assume \(p : \varphi \); then \(\mathsf{in}_1\ p\) contradicts \(h\).
