Rocq already has the lecture's four type formers. With a few notations, we can also write them, and their programs, in the lecture's syntax:

\(\tau_1 + \tau_2\)A + B

\(()\)tt

In types, 1 and 0 now mean unit and Empty_set; in programs they are still the numbers 1 and 0.

In many programming languages, \(\tau_1 + \tau_2\) is the result type \(\mathsf{Result}\ \tau_1\ \tau_2\): either \(\mathsf{in}_1\) of a success value or \(\mathsf{in}_2\) of an error.

\(\mathbf{0}\) has no introduction form, so it has no values, and a case on it has no branches: this is the lecture's \(\mathsf{case}_{\mathbf{0}}\ e\ \{\}\). From an impossible value, you can return anything.

Counting values

For types with finitely many values, write \(|\tau|\) for how many values \(\tau\) has. A pair picks one of each, and a sum picks one side:

\[ |\tau_1 \times \tau_2| = |\tau_1| \cdot |\tau_2| \qquad |\tau_1 + \tau_2| = |\tau_1| + |\tau_2| \qquad |\mathbf{1}| = 1 \qquad |\mathbf{0}| = 0 \]

This is why they are called algebraic data types. For example, \(\mathsf{bool} \times \mathsf{bool}\) has \(2 \cdot 2 = 4\) values, and \(\mathbf{1} + \mathbf{1}\) has \(1 + 1 = 2\), as many as \(\mathsf{bool}\). That is why \(\mathsf{bool}\) is also written \(\mathbf{2}\).

2. Isomorphisms

Two types are isomorphic, \(A \cong B\), when there are functions \(f : A \to B\) and \(g : B \to A\) that undo each other:

\[ g\,(f\, a) = a \text{ for every } a, \qquad f\,(g\, b) = b \text{ for every } b \]

Then \(A\) and \(B\) have the same values, with different names. Each law of the algebra above is an isomorphism.

Every proof below has the same shape: split into the two directions; in each, take the value apart, one case per way it can be built; then each case computes, and reflexivity finishes it.

\(A \times \mathbf{1} \cong A\)

Like \(n \cdot 1 = n\). The second part of the pair can only be \(()\), so it carries no information.

\(A + \mathbf{0} \cong A\)

Like \(n + 0 = n\). The \(\mathsf{in}_2\) side would hold a value of \(\mathbf{0}\), which can't exist, so only \(\mathsf{in}_1\) ever happens.

\(A \times B \cong B \times A\)

Like \(n \cdot m = m \cdot n\). Swapping the pair, twice, gives it back.

\(A \times (B + C) \cong A \times B + A \times C\)

Like \(n(m + k) = nm + nk\). A pair whose second part is "a \(B\) or a \(C\)" is the same as "a pair with a \(B\), or a pair with a \(C\)".

\(\mathsf{bool} \cong \mathbf{1} + \mathbf{1}\)

\(\mathsf{true}\) is \(\mathsf{in}_1\ ()\), \(\mathsf{false}\) is \(\mathsf{in}_2\ ()\), and \(\mathsf{if}\) is a case. So the lecture's language didn't need \(\mathsf{bool}\) built in: sums give it to us.

\(\mathsf{option}\ A \cong \mathbf{1} + A\)

\(\mathsf{None}\) is \(\mathsf{in}_1\ ()\), and \(\mathsf{Some}\ a\) is \(\mathsf{in}_2\ a\): "nothing, or an \(A\)".

Exercise: \(A \times \mathbf{0} \cong \mathbf{0}\)

Like \(n \cdot 0 = 0\). A pair would need a value of \(\mathbf{0}\), so there are no such pairs. Try it before opening the code: what are the two functions, and why do the proofs have no cases?

3. Types as propositions

Read a type as a proposition, and a program of that type as a proof of it. This is the Curry–Howard correspondence, between the simply typed λ-calculus and intuitionistic propositional logic:

typepropositionRocq
\(\tau_1 \times \tau_2\)\(P \wedge Q\)P /\ Q
\(\tau_1 + \tau_2\)\(P \vee Q\)P \/ Q
\(\tau_1 \to \tau_2\)\(P \Rightarrow Q\)P -> Q
\(\mathbf{1}\)\(\top\)True
\(\mathbf{0}\)\(\bot\)False

Erase the terms from a typing rule and you get a rule of logic. A pair is a proof of \(P \wedge Q\) from a proof of each; a case is a proof by cases; a case on \(\mathbf{0}\) is "from false, anything":

\[\frac{\Gamma \vdash e_1 : \tau_1 \quad \Gamma \vdash e_2 : \tau_2}{\Gamma \vdash (e_1, e_2) : \tau_1 \times \tau_2} \quad\leadsto\quad \frac{P \quad Q}{P \wedge Q}\]
\[\frac{\Gamma \vdash e : \tau_1 \times \tau_2}{\Gamma \vdash e.1 : \tau_1} \quad\leadsto\quad \frac{P \wedge Q}{P}\]
\[\frac{\Gamma \vdash e : \tau_1}{\Gamma \vdash \mathsf{in}_1\ e : \tau_1 + \tau_2} \quad\leadsto\quad \frac{P}{P \vee Q}\]
\[\frac{\Gamma \vdash e : \mathbf{0}}{\Gamma \vdash \mathsf{case}_{\mathbf{0}}\ e\ \{\} : \tau} \quad\leadsto\quad \frac{\bot}{R}\]
\[\frac{\Gamma \vdash e : \tau_1 + \tau_2 \quad \Gamma, x_1{:}\tau_1 \vdash e_1 : \tau \quad \Gamma, x_2{:}\tau_2 \vdash e_2 : \tau}{\Gamma \vdash \mathsf{case}_+\ e\ \{\mathsf{in}_1\ x_1 \to e_1 \mid \mathsf{in}_2\ x_2 \to e_2\} : \tau}\]
\[\leadsto\quad \frac{P \vee Q \quad P \vdash R \quad Q \vdash R}{R}\]

Rocq has both columns, A * B at Type and P /\ Q at Prop, and the programs are the same. Here is swap again as a program, and then the same function as a proof that \(\wedge\) is commutative: conj is the pair for /\.

The same proof written with tactics. Print shows the program the tactics built: a match that takes the pair apart and puts it back the other way round.

A case is a proof by cases, a case on \(\mathbf{0}\) is ex falso, and distributivity at Prop is the same function as dist_to:

Steps simplify proofs. The lecture's rule \((v_1, v_2).1 \longrightarrow v_1\) builds a pair and immediately takes it apart. As a proof, that is a detour: prove \(P \wedge Q\), only to use \(P\). The step removes the detour, so evaluating a program is simplifying a proof.

Excluded middle

Can you prove \(P \vee \neg P\)?

Here \(\neg P\) is \(P \Rightarrow \bot\), so as a type it is \(P + (P \to \mathbf{0})\). A program of this type would have to choose \(\mathsf{in}_1\) or \(\mathsf{in}_2\) without knowing anything about \(P\): \(\mathsf{in}_1\) needs a proof of \(P\), and \(\mathsf{in}_2\) needs a way to turn any proof of \(P\) into a contradiction. There is no such program, so \(P \vee \neg P\) can't be proved this way. That is exactly what makes the logic intuitionistic.

But it can't be refuted either: its double negation, \(\neg\neg(P \vee \neg P)\), has a proof. Given \(h : \neg(P \vee \neg P)\), choose the right side; to show \(\neg P\), assume \(p : P\); then \(\mathsf{in}_1\ p\) contradicts \(h\).
