1. Contextual equivalence

When should two programs count as the same? Intensionally, when they are the same code; that is too strict to be useful. Extensionally, when nobody can tell them apart: a compiler could swap one for the other and the program would behave the same. Running time does not count. Halting does, so for a Turing-complete language the question is undecidable.

Closed Booleans first

For closed programs of type \(\mathsf{bool}\) there is a ground truth, what happens when you run them:

\[ e \equiv^{\mathsf{cl}}_{\mathsf{bool}} e' \quad:=\quad (e \longrightarrow^* \mathsf{true} \text{ and } e' \longrightarrow^* \mathsf{true}) \text{ or } (e \longrightarrow^* \mathsf{false} \text{ and } e' \longrightarrow^* \mathsf{false}) \]

So \(\mathsf{true} \equiv^{\mathsf{cl}}_{\mathsf{bool}} (\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5\): one is a value, the other reaches it in a step.

Contexts

A compiler optimizes subterms, which are open and of any type. Reduce their equivalence to the Boolean case by putting them inside a larger program. A context \(C\) is a term with one hole, anywhere, including under a binder:

\[ \begin{aligned} C ::={}& [\,] \mid \lambda x{:}\tau.\, C \mid C\, e \mid e\, C \mid C + e \mid e + C \\ &\mid \mathsf{if}\ C\ \mathsf{then}\ e_1\ \mathsf{else}\ e_2 \mid \mathsf{if}\ e\ \mathsf{then}\ C\ \mathsf{else}\ e_2 \mid \mathsf{if}\ e\ \mathsf{then}\ e_1\ \mathsf{else}\ C \end{aligned} \]

\(C[e]\) puts \(e\) in the hole, capturing: \((\lambda x{:}\tau.\, [\,])[x] = \lambda x{:}\tau.\, x\). Two differences from an evaluation context \(E\): the hole may sit under a λ, and the other positions hold any \(e\), not just values. A value is a semantic notion, about how terms run; a context is pure syntax.

Contexts are typed. \(C : (\Gamma \vdash \tau) \Rightarrow (\Gamma' \vdash \tau')\) means: for every \(e\), if \(\Gamma \vdash e : \tau\) then \(\Gamma' \vdash C[e] : \tau'\). The type of the hole matters, because it dictates what the context can do with what it is given: a Boolean can be tested by an \(\mathsf{if}\), a function can only be applied.

The definition

\[ e \equiv^{\mathsf{ctx}}_{\Gamma \vdash \tau} e' \quad:=\quad \forall C : (\Gamma \vdash \tau) \Rightarrow (\cdot \vdash \mathsf{bool}).\ C[e] \equiv^{\mathsf{cl}}_{\mathsf{bool}} C[e'] \]

Closed Booleans play the role of C's main: the only programs we ever actually run. Everything else is equal when, for the purpose of producing Booleans, it always does the same thing. This is the gold standard of extensional program equivalence, also called observational equivalence. With effects one often closes at type \(1\) instead, because the effects already tell everything apart.

Proving one

Are \(\mathsf{true}\) and \((\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5\) contextually equivalent? Directly from the definition, the proof is by induction over all contexts: a case for every constructor of \(C\). Painful, for something that is one reduction step. So first a general principle:

\[ \textbf{Conjecture.}\quad \text{If } e \longrightarrow^* e' \text{ then } e \equiv^{\mathsf{ctx}}_{\cdot \vdash \mathsf{bool}} e'. \]

Section 2 proves it. Now an open example, where no step applies because we do not reduce under λ:

\[ \lambda y{:}\mathsf{int}.\, \mathsf{true} \;\overset{?}{\equiv^{\mathsf{ctx}}_{\cdot \vdash \mathsf{int} \to \mathsf{bool}}}\; \lambda y{:}\mathsf{int}.\, (\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5 \]

The same two terms, each under a λ. The conjecture does not apply: neither side steps.

\[ \begin{gathered} \lambda y{:}\mathsf{int}.\, \mathsf{true} \;\overset{?}{\equiv^{\mathsf{ctx}}}\; \lambda y{:}\mathsf{int}.\, (\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5 \\[6pt] \text{Let } C : (\cdot \vdash \mathsf{int} \to \mathsf{bool}) \Rightarrow (\cdot \vdash \mathsf{bool}). \quad \text{Want } C[\lambda y.\, \mathsf{true}] \equiv^{\mathsf{cl}}_{\mathsf{bool}} C[\lambda y.\, (\lambda x.\, \mathsf{true})\, 5]. \end{gathered} \]

Unfold the definition: take any closing context for the function type.

\[ \begin{gathered} \lambda y{:}\mathsf{int}.\, \mathsf{true} \;\overset{?}{\equiv^{\mathsf{ctx}}}\; \lambda y{:}\mathsf{int}.\, (\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5 \\[6pt] \text{Let } C : (\cdot \vdash \mathsf{int} \to \mathsf{bool}) \Rightarrow (\cdot \vdash \mathsf{bool}). \quad \text{Want } C[\lambda y.\, \mathsf{true}] \equiv^{\mathsf{cl}}_{\mathsf{bool}} C[\lambda y.\, (\lambda x.\, \mathsf{true})\, 5]. \\[6pt] \text{Know: } \mathsf{true} \equiv^{\mathsf{ctx}}_{\cdot \vdash \mathsf{bool}} (\lambda x.\, \mathsf{true})\, 5. \qquad \class{hl-blue}{\bbox[#eef1f6,2pt]{\text{Take } C' = C[\lambda y{:}\mathsf{int}.\, [\,]].}} \end{gathered} \]

The bodies are equivalent, by the conjecture. Build a context for them: \(C\) with a λ in its hole.

\[ \begin{gathered} \lambda y{:}\mathsf{int}.\, \mathsf{true} \;\equiv^{\mathsf{ctx}}\; \lambda y{:}\mathsf{int}.\, (\lambda x{:}\mathsf{int}.\, \mathsf{true})\, 5 \\[6pt] \text{Let } C : (\cdot \vdash \mathsf{int} \to \mathsf{bool}) \Rightarrow (\cdot \vdash \mathsf{bool}). \quad \text{Want } C[\lambda y.\, \mathsf{true}] \equiv^{\mathsf{cl}}_{\mathsf{bool}} C[\lambda y.\, (\lambda x.\, \mathsf{true})\, 5]. \\[6pt] \text{Know: } \mathsf{true} \equiv^{\mathsf{ctx}}_{\cdot \vdash \mathsf{bool}} (\lambda x.\, \mathsf{true})\, 5. \qquad \text{Take } C' = C[\lambda y{:}\mathsf{int}.\, [\,]]. \\[6pt] C'[\mathsf{true}] \equiv^{\mathsf{cl}}_{\mathsf{bool}} C'[(\lambda x.\, \mathsf{true})\, 5], \quad \text{and these are } C[\lambda y.\, \mathsf{true}] \text{ and } C[\lambda y.\, (\lambda x.\, \mathsf{true})\, 5]. \ \square \end{gathered} \]

\(C'\) is a closing Boolean context for the bodies, so it gives them the same answer; and \(C'[e]\) is exactly \(C[\lambda y.\, e]\).

Congruence and adequacy

That argument is a general principle. Congruence: equivalent terms stay equivalent inside any context. Adequacy: at closed Booleans, contextual equivalence implies the closed equivalence, by taking the context to be the hole.

\[\frac{e \equiv^{\mathsf{ctx}}_{\Gamma \vdash \tau} e' \qquad C : (\Gamma \vdash \tau) \Rightarrow (\Gamma' \vdash \tau')}{C[e] \equiv^{\mathsf{ctx}}_{\Gamma' \vdash \tau'} C[e']}\ \text{(congruence)}\]
\[\frac{e \equiv^{\mathsf{ctx}}_{\cdot \vdash \mathsf{bool}} e'}{e \equiv^{\mathsf{cl}}_{\mathsf{bool}} e'}\ \text{(adequacy)}\]

In Rocq, congruence is the composition of contexts, and adequacy is three lines.

These two properties characterize it:

\[ \textbf{Theorem.}\quad \equiv^{\mathsf{ctx}} \text{ is the greatest adequate congruence relation.} \]

Greatest: if \(R\) is any family of relations on well-typed terms that is adequate and a congruence, then \(e\, R\, e'\) implies \(e \equiv^{\mathsf{ctx}} e'\). Some authors take this as the definition. It is also the strategy: never prove contextual equivalence directly. Find a relation that is convenient to prove, show it is an adequate congruence, and contextual equivalence follows.

2. Denotational equivalence

A relation we already have, from Discussion 8:

\[ e \equiv^{\mathsf{den}}_{\Gamma \vdash \tau} e' \quad:=\quad [\![e]\!]_{\Gamma \vdash \tau} = [\![e']\!]_{\Gamma \vdash \tau} \]
\[ \textbf{Theorem.}\quad \equiv^{\mathsf{den}} \text{ is an adequate congruence. Hence } e \equiv^{\mathsf{den}} e' \text{ implies } e \equiv^{\mathsf{ctx}} e'. \]

Adequacy. Let \(\cdot \vdash e, e' : \mathsf{bool}\) with \([\![e]\!] = [\![e']\!]\). These are functions \(\{*\} \to \{\mathsf{true}, \mathsf{false}\}\).

Equal denotations of two closed Booleans.

Adequacy. Let \(\cdot \vdash e, e' : \mathsf{bool}\) with \([\![e]\!] = [\![e']\!]\). These are functions \(\{*\} \to \{\mathsf{true}, \mathsf{false}\}\).

\[ [\![e]\!](*) = \mathsf{true} \iff e \longrightarrow^* \mathsf{true} \qquad [\![e]\!](*) = \mathsf{false} \iff e \longrightarrow^* \mathsf{false} \]

Discussion 8's adequacy at \(\mathsf{bool}\), both ways: a closed Boolean reduces to its meaning, and it reduces to only one thing.

Adequacy. Let \(\cdot \vdash e, e' : \mathsf{bool}\) with \([\![e]\!] = [\![e']\!]\). These are functions \(\{*\} \to \{\mathsf{true}, \mathsf{false}\}\).

\[ [\![e]\!](*) = \mathsf{true} \iff e \longrightarrow^* \mathsf{true} \qquad [\![e]\!](*) = \mathsf{false} \iff e \longrightarrow^* \mathsf{false} \]

So \(e\) and \(e'\) reduce to the same Boolean, and every closed Boolean reduces to one of the two. \(\square\)

The hard-fought theorem pays off: the logical relation of Discussion 8 bought this line.

Congruence. Let \([\![e]\!] = [\![e']\!]\) and \(C : (\Gamma \vdash \tau) \Rightarrow (\Gamma' \vdash \tau')\). Want \([\![C[e]]\!] = [\![C[e']]\!]\).

One case per kind of context? No: one lemma covers them all.

Congruence. Let \([\![e]\!] = [\![e']\!]\) and \(C : (\Gamma \vdash \tau) \Rightarrow (\Gamma' \vdash \tau')\). Want \([\![C[e]]\!] = [\![C[e']]\!]\).

\[ \textbf{Compositionality.}\quad [\![C[e]]\!] = [\![C]\!]\,([\![e]\!]) \qquad\text{where } [\![C]\!] : ([\![\Gamma]\!] \to [\![\tau]\!]) \to ([\![\Gamma']\!] \to [\![\tau']\!]) \]

The third version of compositionality, after the ones for evaluation contexts and for substitution, and the most general: the meaning of a context is a function of the meaning of what fills it.

Congruence. Let \([\![e]\!] = [\![e']\!]\) and \(C : (\Gamma \vdash \tau) \Rightarrow (\Gamma' \vdash \tau')\). Want \([\![C[e]]\!] = [\![C[e']]\!]\).

\[ \textbf{Compositionality.}\quad [\![C[e]]\!] = [\![C]\!]\,([\![e]\!]) \qquad\text{where } [\![C]\!] : ([\![\Gamma]\!] \to [\![\tau]\!]) \to ([\![\Gamma']\!] \to [\![\tau']\!]) \]
\[ [\![C[e]]\!] = [\![C]\!]\,([\![e]\!]) = [\![C]\!]\,([\![e']\!]) = [\![C[e']]\!]. \ \square \]

Substitute equals for equals. Compositionality is the fact that every clause of \([\![\cdot]\!]\) is a function of the meanings of the subterms, packaged once.

This is the practical payoff of a denotational semantics. Contextual equivalence is defined indirectly, through every context; denotational equivalence is an equation between functions, and all of mathematics is available to prove it. The first example: \([\![\mathsf{true}]\!](*) = \mathsf{true}\) and \([\![(\lambda x.\, \mathsf{true})\, 5]\!](*) = [\![\mathsf{true}]\!](*, x \mapsto 5) = \mathsf{true}\), so the two are contextually equivalent. In Rocq the two meanings are equal by computation.

The conjecture follows the same way: if \(e \longrightarrow^* e'\) then \([\![e]\!] = [\![e']\!]\) by soundness, hence \(e \equiv^{\mathsf{ctx}} e'\).

Is denotational equivalence complete for contextual equivalence?

Does \(e \equiv^{\mathsf{ctx}} e'\) imply \([\![e]\!] = [\![e']\!]\)? For the pure simply typed λ-calculus, yes: every type denotes a finite set, so an open term can be checked on every input, and the outputs compared through adequacy. Not in general: with inductive types or non-termination the denotations contain uncomputable functions that no context can tell apart, and the two relations differ. Soundness is the property a useful denotational semantics must have; completeness is a bonus.

3. β and η at every type

Two descriptions of equivalence so far: the definition, which says what it means, and the denotational one, which is how to prove things. Neither says which equations hold. The third description is axiomatic: an inductively defined relation \(e \equiv^{\mathsf{ax}}_{\Gamma \vdash \tau} e'\), a syntactic list of the equations.

Three kinds of rule. First, the equivalence relation rules, reflexivity, symmetry, transitivity. Second, one congruence rule per constructor: the operations of the language respect equality, something proved for the other two relations and simply declared here. Those are the boring ones. The interesting rules come in two families, for each type:

  • β rules, the computation rules: an introduction form inside an elimination form simplifies.
  • η rules, the reasoning or extensionality rules: any term of the type equals an introduction form built from its eliminations.

Each rule below is checked in the model of Discussion 7: a type is a Rocq type, a term with a free variable \(x\) is a Rocq function of \(x\). The proof of each is to compute, or to take a value apart.

Functions: intro \(\lambda\), elim application

\[ (\lambda x{:}\tau.\, e)\, e' \equiv^{\mathsf{ax}} e[x \mapsto e'] \ (\beta) \qquad\qquad e \equiv^{\mathsf{ax}} \lambda x{:}\tau_1.\, e\, x \ (\eta) \quad\text{for } \Gamma \vdash e : \tau_1 \to \tau_2 \]

Two differences from the step rule \(E[(\lambda x{:}\tau.\, e)\, v] \longrightarrow E[e[x \mapsto v]]\). The axiom applies to open terms, which a compiler optimizing a function body needs. And the argument is any \(e'\), not a value: the step rule fixed an evaluation order to be deterministic, the axiom is the most general principle, and it had better be at least as general as the rule, since every step is an equivalence. The η rule says nothing about evaluation; it emerges from the definition of contextual equivalence.

The alternative form \(\eta'\): two functions are equal when they agree on a fresh variable \(x\), that is \(e\, x \equiv e'\, x\) under \(\Gamma, x{:}\tau_1\). A syntactic for-all. Given β, each form of η implies the other.

Products: intro \((e_1, e_2)\), elim \(e.1\), \(e.2\)

\[ (e_1, e_2).i \equiv^{\mathsf{ax}} e_i \ (\beta) \qquad\qquad e \equiv^{\mathsf{ax}} (e.1, e.2) \ (\eta) \qquad\qquad \frac{e.1 \equiv e'.1 \quad e.2 \equiv e'.2}{e \equiv e'} \ (\eta') \]

Unit: intro \(()\), no elim

No elimination, so no β: nothing to put an introduction inside. There is an η: every term of type \(1\) is \(()\), so any two are equal. The one-element set, in one rule.

\[ e \equiv^{\mathsf{ax}} () \ (\eta) \quad\text{for } \Gamma \vdash e : 1 \qquad\qquad \frac{\Gamma \vdash e, e' : 1}{e \equiv e'} \ (\eta') \]

Sums: intro \(\mathsf{inl}\), \(\mathsf{inr}\), elim \(\mathsf{case}\)

\[ \mathsf{case}\ (\mathsf{inl}\ e)\ \{\mathsf{inl}\ x_1 \to e_1 \mid \mathsf{inr}\ x_2 \to e_2\} \equiv^{\mathsf{ax}} e_1[x_1 \mapsto e] \ (\beta_{\mathsf l}) \qquad \text{and } \beta_{\mathsf r} \text{ likewise} \]

The η rule is where sums differ. The pattern says "\(e\) equals an introduction form", but which one, \(\mathsf{inl}\) or \(\mathsf{inr}\)? The best we can do by the pattern is rebuild \(e\) by a case. True, but weak:

\[ e \equiv^{\mathsf{ax}} \mathsf{case}\ e\ \{\mathsf{inl}\ x_1 \to \mathsf{inl}\ x_1 \mid \mathsf{inr}\ x_2 \to \mathsf{inr}\ x_2\} \ (\text{weak } \eta) \]

The strong η says more: not only a term of sum type, but any term containing one can be rewritten to pattern match on it first. For \(\Gamma \vdash e' : \tau_1 + \tau_2\) and \(\Gamma, x{:}\tau_1 + \tau_2 \vdash e : \tau\),

\[ e[e'/x] \equiv^{\mathsf{ax}} \mathsf{case}\ e'\ \{\mathsf{inl}\ x_1 \to e[\mathsf{inl}\ x_1/x] \mid \mathsf{inr}\ x_2 \to e[\mathsf{inr}\ x_2/x]\} \ (\text{strong } \eta) \]

Weak η is the case \(e = x\). In the model, \(e\) with its free \(x\) is a function \(f\), \(e[e'/x]\) is \(f\, e'\), and the rule is one destruct. Note the side condition in the typing: \(e'\) depends only on \(\Gamma\), so nothing bound inside \(e\) can be captured.

What strong η buys is the commuting conversion: an \(\mathsf{if}\) (or a \(\mathsf{case}\)) sitting inside a term moves out, with the surrounding term pushed into both branches. Weak η plus the commuting conversions is strong η. Compilers do this all the time: in each branch the value is known, so more optimization is possible.

\[ e[\mathsf{if}\ e'\ \mathsf{then}\ e''\ \mathsf{else}\ e'''/x] \equiv^{\mathsf{ax}} \mathsf{if}\ e'\ \mathsf{then}\ e[e''/x]\ \mathsf{else}\ e[e'''/x] \]
Why are sums different? Polarity

Functions, products and unit are negative types: they are used through projections and application, and introduced by saying what to do under each use (sometimes called co-pattern matching). Sums and zero are positive: introduced by constructors and used by pattern matching. Negative types all get the same η pattern; positive types get the stronger one. Both the weak and the strong rule are sound for contextual equivalence; the strong one proves more, and if what you want is to prove contextual equivalences, more is better.

Zero: no intro, elim \(\mathsf{case}_0\)

Dual to unit: no introduction, so no β. The η is the strong one again. For \(\Gamma \vdash e' : 0\) and \(\Gamma, x{:}0 \vdash e : \tau\),

\[ e \equiv^{\mathsf{ax}} \mathsf{case}_0\ e\ \{\} \ (\text{weak } \eta) \qquad\qquad e[e'/x] \equiv^{\mathsf{ax}} \mathsf{case}_0\ e'\ \{\} \ (\text{strong } \eta) \]

Read it as dead-code elimination: a term of type \(0\) in scope is a proof that this code never runs, and the whole term can go. A striking consequence: \(e\) need not even mention \(x\). With \(f : 1 \to 0\) in scope, any \(e : \tau\) is equal to \(\mathsf{case}_0\ (f\, ())\ \{\}\). So deciding this equality means deciding whether \(0\) is inhabited in the current context, which is decidable for STLC and undecidable for dependent types.

Why have \(0\) at all? Rarely to write a program of type \(0\). Polymorphic code instantiated at \(0\) or \(1\) gets a trivial interface; in theorem proving \(0\) is falsehood; and subtyping wants a bottom type. Like having zero among the numbers: the algebra works out.

Soundness and completeness of the axioms

Soundness. \(e \equiv^{\mathsf{ax}} e'\) implies \(e \equiv^{\mathsf{den}} e'\), which implies \(e \equiv^{\mathsf{ctx}} e'\). The proof is the list of lemmas above: every axiom is an equation in the model. The \(0\) cases hold because an element of the empty set is impossible.

Completeness. \(e \equiv^{\mathsf{ctx}} e'\) implies \(e \equiv^{\mathsf{ax}} e'\): however a contextual equivalence was proved, there is a syntactic proof of it from β and η. True for STLC because every type is finite. It breaks as soon as natural numbers with primitive recursion are added: a syntactic proof system would make program equivalence semi-decidable, hence decidable, which it is not. So this is a property of small languages. For a compiler writer the practical reading is the lecture's: β reduction and η expansion are the only equations about functions you will ever need.
